# Public JPEG and image-ratio checkpoint

The compiler now accepts standard 4:2:2 and 4:2:0 baseline/progressive JPEG assets at encoded widths of at least five pixels, preserving their original bytes in ordinary `.riv` files. Narrow subsampled images receive `unsupported-image` because actual native/Chrome comparisons found content-dependent color differences. A proposed tiny-image exception was tested through the public compiler, failed, and was removed. The runtime, renderer, schema and shared dependencies remain unchanged.

This completes a bounded public compiler checkpoint, not I04 or the overall goal. Metadata, other JPEG representations, narrow-image exceptions and wider layout/painting combinations remain open. The 99 backlog items remain **13 qualified, 23 partial, four investigating and 59 pending**.

## Public implementation and validation

- Compiler-owned entropy validation separates real component block grids from padded interleaved MCU storage. It handles single/multiple component scans, odd dimensions, scan-specific restart counts and progressive coefficient refinement. The portable baseline decoder still performs a full decode of admitted images; no pixel transcoding or decoder override was added.
- [Independent scan review](jpeg-subsampling-review.md): **916/916** checks pass—228 new valid files, 108 unchanged 4:4:4 files and 580 targeted controls. Twelve header edits are correctly accepted because their fully interleaved padded data already contains the extra real blocks; 568 malformed controls reject. This evidence concerns syntax/entropy, not native color reproduction.
- Final full build: `output/public-jpeg-build-r2`, **309 Rust tests, 56 Node tests, strict TypeScript and native/WASM builds pass**. Rust integration compiles each public success twice, checks exact embedded bytes and source IDs, and checks the explicit diagnostics. The runtime source guard passes. Project-wide formatting has pre-existing unrelated differences; focused `rustfmt --check` passes both changed production files.
- [Public corpus](public-jpeg-cases.json): **56 cases, 34 successful scenes, 22 diagnostics**. The final CLI/raw ABI/JavaScript results match in all 112 ABI/JS comparisons. Source assets cover baseline/progressive, 4:4:4/4:2:2/4:2:0, even/odd dimensions, one-MCU restarts, width boundaries and tiny rejected controls; PNG controls preserve the corresponding geometry.
- **272/272 geometry, pixel and image-presence frames pass** for the final admitted scenes. Each original and clone resizes through 240×240 → 390×320 → 768×560 → 240×240 using the same emitted bytes. Final R2 files/maps/requests match the measured R1 files exactly; [the combined receipt](../output/public-jpeg-layout-r2/combined-receipt.json) verifies those transfers, the reset, native tools, browser reference, streams, geometry and PNGs. No browser measurement supplies shipping layout or modifies the imported file.
- [Visual review](public-jpeg-visual-review.md): 34 distinct full pairs, with 238 exact RGBA/white-canvas-extension transfers. [Public gallery](../output/public-jpeg-layout-r2/visual/gallery.html). Passing JPEG comparisons still allow small decoded-color differences under the unchanged gates; this is not a bit-identical decoder claim.
- Regression: all 794 historical files/maps remain exact; the earlier40-case image corpus and 12-case ratio corpus preserve all 39 successful files/maps and expected diagnostics. Both also match through raw ABI/JS. The 86-case asset campaign passes 252 final-interface observations, preserving malformed/resource/ownership/recovery behavior. No peak-memory or worst-case-CPU bound is claimed.

The final CLI SHA-256 is `db691584e4447506d7b91faa69eaef8844afd782ef723534452c78f81a6acb33`; WASM is `97b47cbb424dc21c9b4dbf5cb92f3097ab361ce88b03c630d3b7eb2e61b0b1aa`. ## Decoder boundary and rejected exception

The initial private 24-scene codec corpus passes 192 geometry/presence frames and 176 pixel frames, retaining 16 skinny 4:2:0 failures. Two discriminating width/horizontal corpora retain 72 failures across 152 frames. Source content matters: a width-four 4:2:2 image with horizontal stripes passes, while another with colors changing horizontally fails. These are evidence against general fidelity in the context, not a claim that every image fails. [Private codec review](jpeg-subsampling-pixels-review.md), [boundary pixel review](jpeg-chroma-pixels-review.md).

The first public candidate allowed tiny images with one logical chroma sample. Its 2×1 red/green control produced a local RGB error of 7.5 against the unchanged 6 interior gate, including a 28-point red-channel difference in the second pixel. All eight original/clone frames fail; the earlier 2×1 differently colored control merely met the gate. Final admission therefore diagnoses both subsampled representations at widths≤4. The old candidate and its failed frames remain preserved in `output/public-jpeg-layout-r1`; final qualification does not delete or relabel them.

[The source review](jpeg-decoder-boundary-review.md) traces ordinary ImageAsset decoding into the immutable platform decoder. File fit, alignment, clipping and linear/nearest sampling operate on already-decoded pixels; no ordinary property selects the JPEG chroma reconstruction. A fit/sampler wrapper cannot generally repair those content-dependent colors. The exact ImageIO mechanism and possible content-specific exceptions remain unresolved. A uniform browser-matching runtime decoder could be a separate future proposal; it is not implemented here. PNG or 4:4:4 JPEG is an explicit author-supplied alternative, never an automatic conversion.

## Additional aspect ratios and repeatable workflow

Five new authored PNG assets cover portrait, wide, square, odd and very small ratios. Their 12 public scenes pass 96 geometry/presence and 80 pixel frames, retaining 16 local following-sibling edge failures. All 36 distinct pairs were visually reviewed, with 60 exact transfers. The final compiler reproduces those files and source maps exactly; their failures remain visible. [Aspect review](public-image-aspect-review.md), [aspect gallery](../output/public-image-aspect-r1/visual/gallery.html). Earlier image-layout evidence still retains 18 fractional pixel failures; neither corpus qualifies every fit/position or constraint combination.

`public-image-compile.py --cases` freezes a separate corpus and its assets beside requests while preserving the selected compiler snapshot. It rejects directory traversal in names/asset paths. `ordinary-image-build.py` can reuse a verified private generator and now binds the actual custom fixture generator. `public-image-visual.py` accepts general corpus sizes and explicit prior-native comparisons; visual completion still requires direct inspection. Exact commands and source snapshots remain in receipts.

The public case generator reproduces the final corpus byte-for-byte while verifying and reusing encoded tiny controls without rewriting them. Its initial manifest-field adapter failure and exact historical generator revisions remain in `output/public-jpeg-cases-generation-r1`. The boundary gallery's initial sheet-spacing defect is also preserved; corrected sheets were independently checked against the original image pixels. Neither issue changed the native render evidence.

Next implementation should advance another unfinished compiler context with a finite acceptance matrix—image padding/constraints, for example—rather than repeat the completed chroma-boundary experiments. Narrow exceptions require a new testable file-level hypothesis. Keep the immutable contract and all 99 items intact.
