# Public value token tests and historical migration

The frozen compiler passes **262 Rust tests and 42 Node tests**. Native/WASM builds, strict TypeScript and the immutable-runtime guard also pass. The build reports unchanged inputs, and this review independently matched all 116 source snapshots plus both frozen binaries. Exact commands, logs and hashes are bound by `public-value-token-receipt.json` and `output/public-value-build-r1/frozen/source-bindings.json`.

The public corpus contains **610 cases** exercised at 240×160 and 768×120: 307 compare complete bytes/maps with independent literal or `unset` controls, 292 require diagnostics, and 11 compare the diagnostic code/message with explicitly authored `unset` because the corresponding CSS initial semantics remain unsupported. CLI and WASM must agree on complete output or diagnostics, emit no files on rejection, and preserve previously owned output across subsequent calls. Nine focused Rust tests cover this corpus; the migrated integration set passes 73 tests across 12 targets.

Coverage includes non-CSS whitespace at value edges and component boundaries; escaped content remaining within its original token; literal/variable primitive types, arity and signs; current priority, inheritance, shorthand and order behavior; CSS whitespace/comments/ASCII escapes; distinct Unicode custom-property names; and NBSP/vertical-tab HTML text rejection. Underflow controls distinguish invalid nonzero authored coefficients that round to f32 zero from valid zero/positive-length cases. These are bounded receiving-grammar tests, not a claim of complete modern CSS support.

Historical rejection fixture files were preserved byte-for-byte. Twenty-five explicit source-identical controls now assert qualified recovery: one content-box case, three variable-recovery cases, twelve empty-variable cases and nine numeric-token cases. Existing Rust and transport loops verify original HTML/CSS identity before comparing with the independent `unset` control. Inline historical tests likewise enumerate which primitive invalid variables recover; they retain literal, resource and valid unsupported diagnostics. No test infers its expected result from the production classifier or accepts whichever outcome compilation returns.

Retained boundaries include opaque functions, unknown grammar, unsupported units/layout/paint semantics and resource limits. `safe normal` / `unsafe normal` remain unclassified due the draft/Chrome discrepancy. `revert-rule`, including custom declarations, and background clipping values `text` / `border-area` remain diagnostic. Browser-valid unitless `1e-500` remains outside current target admission; `-1e-500px` is compared with `-0px`. Bare top-level `!` is a declaration-syntax rejection; slash is the primitive punctuation recovery control. The custom-property restriction is defined in [CSS Variables §2.1](https://www.w3.org/TR/css-variables-1/#syntax).

The original red runs and their exact inputs remain in `output/public-value-token-red-r1/` and `red-r2/`; the intermediate migration failure remains in `output/public-value-tests-migration-r1/`. Their known fixture corrections are explicit in the earlier receipts: background position lengths are valid CSS, font-size percentages already compile, and bare `!` cannot form the intended custom-property primitive. The final migration result is in `output/public-value-tests-migration-r2/`.

This receipt qualifies public parsing, recovery and transport behavior. It does not transfer browser geometry or pixels, claim native rendering equivalence, broaden numerical limits, or modify the immutable runtime. Native/Chrome original/clone resize evidence and prior-output regression remain separate required receipts owned by the parent validation workflow.
