Before staging any coordinator, the launcher required a clean tracked checkout and captured Git commit `7a928d45c177873ba1c0129fda522f453c13aed1` and tree `a70d14fdb87d9efe4b3a75dd397d53e0257a42fe`. It extracted the bootstrap Python directly from that commit object; that exact bootstrap then read shell, Python, Node, and driver bytes from the captured commit's Git blobs, recorded the same commit/tree in the bundle manifest, and reverified the source identity before the launcher replaced itself with the sealed shell. Therefore a coordinator changed before staging is rejected as dirty, and a swap restored after staging cannot influence the Git-blob bundle. All subsequent preparation, sealing, browser coordination, and finalization used the immutable copies. The Node process independently reported its executed identity for final verification. The browser read and verified the exact HTML and driver bytes from the seal, served and executed them only from SHA-addressed intercepted URLs, fetched the exact sealed wasm-bindgen JavaScript and Wasm buffers, and reported all four executed browser artifact identities for verification. Each of the five fixture files expanded to all three authored corpus samples (`0s`, `0.5s`, and `1s`); each browser and native run recorded and verified the same fixture ID, sample index, and sample seconds before comparison. Native measurement copied the verified runner bytes to a private content-addressed executable and invoked only that sealed copy.
