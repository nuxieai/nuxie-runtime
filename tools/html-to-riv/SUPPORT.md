# Current admission on the unchanged runtime

The initial public compiler is implemented; a qualified release is not yet claimed. “Admitted” below means accepted by the current compiler, not that every combination has completed browser/native qualification. All earlier backlog items remain subject to immutable-target requalification.

Admission is strict: the complete stylesheet is validated, including unmatched or overridden declarations. Variable expressions receive syntax validation globally and value admission in each matching element context; unused custom data does not admit new rendered semantics. Unsupported declarations do not silently disappear merely because they would lose the cascade. Rules that match host `html` or `body` are rejected; style authored box elements. A universal rule can therefore be rejected because it also matches a host element. This differs intentionally from a permissive browser's error recovery.

## Intentional exclusions and unresolved work

- Text rendering, font assets, SVG and other media are not admitted. Image bytes are admitted only in the profile below.
- Borders, border-radius, nonzero/percentage margins, flex wrapping/grow/shrink, align-content, aspect ratio and positioning are not in the public declaration whitelist yet. Flex directions and the item/main-axis alignment profiles listed above are admitted. Ordinary-file experiments do not expand public support.
- Gradients, background-image/repeat, group opacity, transforms, clipping/overflow, decoration and blending declarations are not admitted.
- Custom registrations and variable mutation, calc(), relative units beyond the admitted em/rem contexts, at-rules/media queries and stylesheet nesting are not in the current public computed-style path. Parser-internal groundwork does not establish admission.
- CSS Grid, scripts, interactions, bindings, animation and editor integration remain excluded. No implicit raster, fixed-layout or recompile-on-resize fallback is enabled.
- No CSS runtime requirements, policy installation, custom glyph rendering mode, new stream command or shader extension can be required by emitted files. The 36 former custom capabilities are unavailable; another ordinary-file encoding may still prove a feature possible.

## Authored image contract and remaining boundaries

Asset keys are nonempty, exact and case-sensitive. `src="logo"` resolves only the supplied `logo` key; URL-looking keys are identifiers too. There is no fetch, path lookup, optional prefix, runtime asset loader or caller-supplied dimension override. Duplicate raw JSON names reject. All supplied assets, including unused ones, are validated and embedded. Exact encoded byte strings deduplicate in sorted key order; different encodings of identical pixels remain distinct assets. No pixels are transcoded or normalized.

| Representation | Current admission | Intentionally outside this initial profile |
| --- | --- | --- |
| PNG | Noninterlaced 8-bit RGB/RGBA; IHDR, IDAT and IEND; complete decoding, chunk CRC and exact zlib/checksum validation | Palette/grayscale/other depths, interlace, ancillary color/orientation metadata, animation and other transparency encodings |
| JPEG | Neutral JFIF or untagged 8-bit three-component 4:4:4 Huffman baseline/progressive; complete scans and coefficient precision; at most 64 scans | Subsampling, grayscale/CMYK, EXIF/ICC/other metadata, arithmetic/lossless processes and incomplete progressive previews |
| WebP | Simple static VP8 or VP8L; opaque lossy/lossless and VP8L alpha | VP8X/ALPH extended containers, animation, orientation and color metadata |

Malformed known data returns `invalid-image`; unqualified formats/representations return `unsupported-image`. Invalid asset keys use `invalid-asset`, exceeded asset bounds use `asset-limit`, missing/empty image src uses `missing-image-source`, and unresolved exact keys use `missing-image`. Typed request/byte-shape errors use `invalid-request`. Unsupported CSS/image combinations remain target diagnostics. Failed compilation publishes no new scene.

The image layout profile supports zero own padding/margins, default zero minima and absent maxima, and stretch or start alignment. Both-auto start alignment uses intrinsic dimensions from encoded bytes. Both-auto stretch uses a responsive 100% cross axis plus the existing aspect-ratio field; a fixed main axis with an automatic stretched cross axis preserves CSS stretch distortion. Fixed/percentage axes, fit, clipping, order and reverse directions have bounded public evidence. Own padding, nondefault min/max, automatic margins, alignment wrappers/baselines, unresolved intrinsic percentage chains and nonlegacy flex growth diagnose. These are unfinished compiler contexts, not proof that every ordinary-file composition is impossible.

Object fit/position do not inherit implicitly in the pinned Chrome profile; explicit inherit works. Sampling inherits. Definitely invalid substituted primitive values compute as unset at the original cascade priority; valid unsupported positions, newer fit/sampling values, vendor extensions and opaque functions retain diagnostics. See [image variable recovery](validation/image-variable-recovery-review.md).

The [public image checkpoint](validation/public-image-checkpoint-review.md) passes **216/216 geometry, 198/216 pixel and 216/216 presence comparisons** over the same original and cloned files. Eighteen fractional paint failures remain visible: proportional image height followed by a small tail, fractional linear/nearest sampling, and fractional contain alignment. `pixelated` maps to the existing nearest sampler; this does not establish general CSS pixelated equivalence at fractional scales. The current visual assets share a 96:64 ratio; all admitted aspect ratios and numeric extremes are not visually qualified. Do not mistake accepted input or a whole-frame pass for universal browser fidelity.

Asset limits are 256 supplied names, 16 MiB aggregate encoded bytes **before deduplication**, 8192 per axis and 16 MiB RGBA footprint per image. Portable compiler decoding makes admission consistent across native/WASM; it does not replace real native decode/render validation. The RGBA bound is not a total memory cap: progressive coefficient storage and transport buffers add memory. JS copying/JSON serialization and CLI input reading occur before semantic asset rejection; peak process memory and worst-case CPU remain unqualified. Boundary/parity/recovery evidence is in [the asset review](validation/public-image-assets-review.md).

Resource bounds currently enforced: viewport dimensions in `(0,16384]`; combined HTML/CSS UTF-8 length at most 1 MiB; at most 8192 authored elements; nesting guard 128; authored size/padding coefficients between 0 and 1000000; selector list/rule expansion limits 1024 and selector nesting 32. Derived content-box outer dimensions may exceed the source limit when fixed padding is added (up to 3000000 for three maximum point inputs); this does not establish geometry or pixel fidelity across that range. The WASM bridge additionally caps serialized requests at 192 MiB. Inputs exceeding the compiler's smaller authoring limits still fail compilation.

Q06 has [partial resource-boundary evidence](validation/public-resource-boundaries-review.md): 40 cases pass all 120 CLI/raw-WASM/public-JS observations around the 1 MiB decoded source, 128-level nesting and 8192-authored-element limits. Cases include multibyte UTF-8, split HTML/CSS totals, escaped JSON, plain/content-box structures and combined-limit precedence. Each interface returns 25 successes and 15 expected diagnostics, with exact results, repeated/no-op output files, retained outputs and recovery. The [integration review](validation/public-resource-boundaries-integration-review.md) records the exact lifecycle scope. Other limits, expansion-heavy CSS and broader resource interactions remain open; this adds no language, performance or rendering qualification.

Resolved definite percentage chains are checked against the complete viewport range before emission, including native min/max clamps and lower bounds through automatic minima. Known nonfinite chains diagnose; unknown intrinsic sizes and aggregate position/precision bounds are not generally proven. See validation/numeric-guard-review.md.
