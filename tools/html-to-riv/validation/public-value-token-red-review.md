The public compile test is `tests/value-token-boundaries.rs`. Its generated source corpus is `validation/public-value-token-cases.json`, generated by `validation/public-value-token-fixtures.py`. The 550 cases cover literal/variable non-CSS whitespace and escaped token content, primitive wrong types, arity, nonnegative grammars, inheritance/order/cascade, actual CSS whitespace/comments, Unicode custom-property names, and retained unsupported/unclassified controls. Each case is exercised at 240×160 and 768×120.

Variable recovery failures are separately recorded; this run does not establish the future classifier's implementation.

Two **fixture corrections are required before treating this corpus as the future acceptance gate**:

1. `invalid-important-background` uses `--bad:2px`. A length can form a valid CSS background-position value, so it belongs to valid unsupported semantics rather than definite invalid grammar. Replace this one intended wrong-type source with a quoted string and preserve a distinct valid-unsupported background-position diagnostic control. The r1 failure is not a compiler recovery bug.
2. `unsupported-{literal,variable}-font-percentage` uses `font-size:120%`, which this compiler already supports. Remove those diagnostic expectations or replace them with independently authored valid controls. Their r1 failures are not compiler bugs.

No correction or follow-up run was performed after the parent's stop instruction. The current new files therefore intentionally retain the exact r1 inputs pending that correction; the receipt identifies them explicitly. Three other failing retained controls are malformed known color functions containing NBSP. They currently compile, and must remain diagnostic if this checkpoint leaves their receiving grammar unclassified. Opaque functions must not broadly recover to `unset`.

Resume by correcting those fixture classifications, preserving r1 evidence, and rerunning a red checkpoint before changing production callers. Then implement a conservative `Valid` / `Invalid` / `Unclassified` receiving-value classifier and strict CSS token-boundary handling. Valid unsupported CSS, resource failures, opaque functions and unresolved grammar must remain diagnostic.
