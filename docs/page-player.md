# Shared page player

`nuxie_runtime::page_player`, also exported as `nuxie::page_player`, owns the frame order for published pages. The C API calls this implementation. Preview can use it through ProductHost without reproducing the C frame loop.

## Entry points and ownership

Keep a `PagePlayer` alongside an `ArtboardInstance` and its `Playback`. Pass bound and global view-model roots as subscriptions. For a scripted import, pass its `ScriptedFile` as `Effects`; that integration owns the script checkpoint and command drain.

- `step` accepts indexed inputs, pointers, focus inputs and elapsed seconds. Its owned `Output` contains events, view-model changes, host commands, input results, state changes and scheduling flags.
- `step_begin`, `step_end` and `set_row_collapsed` use the same transaction and failure boundary. `None` is the Rust spelling of a C NULL-name cut. Events and commands generated by status operations are deferred to the next ordinary step, including when their row sleeps before that step.
- `operation` is the staged form used by the C adapter. Its `PendingStep` keeps the frame scope, transaction, host rule scope and occurrence guard alive while the adapter publishes its ABI result. Dropping an uncommitted mutated operation rolls values back and poisons the occurrence. C handle validation, caller-memory conversion and ABI size checks remain in the adapter.
- `content_height` returns the top expanded Screen's intrinsic height in points after a step. C exposes the same query as `nux_player_content_height(player, &height)`.

The shared operation owns frame scope, eager or lazy checkpoint, input dispatch, advance, live-move follow, event ownership, script effects, value-policy resolution and subscription filtering. Native occurrence state prevents reentry and retains terminal failure across different player wrappers. Ordinary preflight refusals remain recoverable.

## Page shape and row ordering

The existing one-time root capability decision now accepts `$nuxie.page` with a `screens` component list even without records. Legacy roots with LiveStep records remain supported. A record-free ordinary root keeps its negative decision and allocates no live-move scene state.

Begin, end and row sleep first flush pending binding changes and settle component updates. Insertions, removals and moves therefore take effect before row lookup and ownership transfer. This also settles the fresh incoming row's opacity and transforms before flight validation.

After settlement, begin and end evaluate the expanded incoming and outgoing Screen machines through the port of Rive’s `StateMachineInstance::tryChangeState()` (`try_change_state`). This updates data bindings and layer states directly, with no advance call. Named steps select their published endpoints; NULL-name cuts use the expanded Screens supplied by the host. Row collapse evaluates that row before putting it to sleep; wake evaluates it immediately after restoring bindings. These evaluations observe intermediate lifecycle phases and reset completed one-shot arrival states before another identical `entering`/transition pair. They advance no timeline, nested artboard or page machine. The endpoint cost test now requires zero artboard advances for begin, end, sleep and wake, with either 2 or 40 expanded rows.

The player snapshots evaluation reports before native queues can be cleared or hidden by collapse. It uses the ordinary event cursor, preserves native listener queues and queues reports alongside host commands in the status transaction. Status outputs contain neither events nor commands. The next committed ordinary step delivers the queued effects once, even if the producing row is still asleep. Projection uses the ordinary event count, property and byte limits. Ordinary files without page shape never enter row evaluation, and sleeping rows still cost no per-frame playback or event walks.

The host controls stack order through the view-model list. Move the incoming row just above the outgoing row for forward navigation and just below it for back navigation, then call begin in the same batch. List moves retain row instance identity, playback, view model and sleep state. The player does not clone or recreate a kept row.

## Checked scripts in Screen rows

During a page operation, checked scripts address the executing Screen row’s root view model under the empty root name (`""`). The published `responses.set` adapter therefore resolves paths such as `experience/responses:form/field` on that row, rather than on the page model whose only field is `screens`. Named global roots retain their existing meaning. A standalone player continues to use its bound root.

The VM enters an execution-source scope for callbacks and generators, and restores the previous source on return or error. Retained property listeners, Promise handlers, async continuations and draw visitors capture their registering owner through `ScriptCallbackScope`. Host method lookup enters the owner before any Lua `__index` getter can execute. The captured owner retains a weak source slot, resolved at invocation. The shared page player resolves that source’s live DataContext ancestry against the current page’s awake row contexts. Context identity distinguishes owning occurrences even when they share a file, schema or VM values, and follows a nested unit to its current Screen. Sleeping rows are excluded from this lookup.

Checked scalar writes, atomic batches and list reads use the same root resolver. Both the C API and ProductHost call these shared helpers. The host’s original policy operation, change capture and graph transaction remain shared across the whole page: a rejected batch changes none of its candidate properties, and a later script failure rolls back earlier row writes and commands in the same step. Clearing choices with nil updates their picked flags without removing the records.

Deferred commands and their deferred events are admitted together under the existing 8 MiB result ceiling. The shared player checks the retained Rust payload; the C API also runs its exact flattened-result accounting against the retained effects before committing the status call. `LimitExceeded` refuses the candidate payload, preserves previously admitted queues, rolls back uncommitted VM writes and leaves the occurrence usable. Status output still publishes no commands or events. Hosts using staged operations can inspect `PendingStep::deferred_effects()` for their own concrete result accounting and use `reject_deferred()` for a recoverable admission refusal.

Begin and end use one report collection before and one after the whole row-evaluation batch. NULL-name cuts therefore walk the expanded occurrence tree twice, rather than twice per Screen. Sleep and wake retain their one-row evaluation boundary. Deferred and newly drained reports are sorted by their native host sequence before projection, preserving emission order even when an older page event is observed after a newer deferred row event.

## Reported event sources

`OwnedPlayerEvent.context` retains the ordinary Rust player's `StateMachineEventContext`, including its path, repeated-item occurrence records and VM identity. It is an owned snapshot taken at drain time. Repeated items can share both the event definition and VM identity; their occurrence records still distinguish them. The emitted order is unchanged.

`source_artboard_global_id` identifies the source artboard containing `event_local_index`. The containing-host path alone cannot supply that address for a nested unit. Both the native Rust report and the shared owned result expose this address. Context vectors count toward the existing 8 MiB event/result budgets, with checked arithmetic before cloning. The C result's aggregate accounting includes their retained storage too.

The C event view and its accessors currently expose VM identity but no path, occurrence or source-artboard address, for either ordinary or page players. This change adds no C ABI surface; Preview can read the Rust fields. Publication and rollback retain the existing transaction boundary: rejected steps return no output, and dropping an uncommitted result discards its context snapshot with the rest of the output.

## Content measurement

After the ordinary step settles layout, the query selects the last active Screen in list order. It copies only that Screen's subtree from the persistent Taffy tree and measures it with the runtime's existing solver and leaf measurement callback, at the page width with unconstrained height. It never publishes the scratch layout, advances playback or drains events.

The owning layout tree caches one answer by Screen node and width. Repeated queries reuse it; the next normal layout solve invalidates it. The first query after a relevant solve costs one intrinsic subtree solve, so this is not a second implementation of layout and is not a zero-work query on a changed frame. Sleeping rows and other Screens are not measured.

Scripted layout uses its last natural measurement from the ordinary layout pass. The query never executes script callbacks. It returns an error if a settled Screen layout tree or required natural measurement is unavailable. An empty expanded stack returns NotFound. Callers should query after stepping, including after changing page width or bound text.
