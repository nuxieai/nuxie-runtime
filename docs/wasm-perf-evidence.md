It extracted the bootstrap Python directly from that commit object; that exact bootstrap then read shell, Python, Node, and driver bytes from the captured commit's Git blobs, recorded the same commit/tree in the bundle manifest, and reverified the source identity before the launcher replaced itself with the sealed shell. The sealed shell rejects an inherited bundle before reading runtime environment variables unless its directory has an exact 64-character lowercase SHA-256 name, the manifest digest matches that name, the manifest records the current clean source commit/tree, and the directory contains exactly the four hash-verified coordinator members. A post-seal replacement of the bundled Python path therefore cannot change the finalizer code, even if the replacement is restored before provenance revalidation.
