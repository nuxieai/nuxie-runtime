# Standalone compiler against an immutable runtime

**Current decision:** PR #629 is merged and the baseline is restored. Static rasterization, fixed-viewport output, host wrappers and recompilation on resize mentioned below are tradeoff candidates outside the approved responsive-file contract; none is adopted. File-level ordinary-Rive compositions are the only shim strategy currently authorized. See ../TARGET.md.

Audit date: 2026-09-11. This is a read-only design audit of the retained compiler, not qualification of a replacement. The required runtime baseline is **6c7ac16617835b5f581784ff08a9e779bb52faf3**. Runtime, renderer, schema and vendored dependency changes from the compiler work must not be prerequisites. Root is reverting the feature work separately. No builds or production edits were performed for this audit; the unfinished private radial parser must not be carried into a replacement merely because its files exist.

## Finding

The current compiler does not produce self-sufficient browser-equivalent Rive scenes. It produces ordinary Rive records **plus a runtime policy program** in `RuntimeRequirements`. `examples/probe.rs` reads that program, mutates imported fonts, Text, LayoutComponent and Artboard objects, and then records the result. Several policies also require modified layout solver and renderer code. Passing the current browser or lifecycle suites therefore does not prove compatibility with the immutable baseline. Removing the requirements file while retaining admission would silently lose semantics; moving its application into another host adapter would retain the forbidden side channel.

The replacement must emit a complete ordinary Rive scene, import it through the unchanged baseline API, and reject any authored behavior it cannot express faithfully. A source map can remain diagnostic metadata; rendering must not consume it. Compiler-side preprocessing and ordinary-object generation are possible implementation strategies, but all alternatives below are **unproven** until baseline import, resize/clone and browser tests establish equivalence.

## Evidence inspected

Current `src/requirements.rs` defines and validates versions 1–26 and the capabilities below. `src/lib.rs:221` begins requirement collection; lines 250–298 select global paint/order and versions 17–26; lines 906–1008 select layout policies; lines 1041–1271 select text policies. `examples/probe.rs:38` reads the sidecar; lines 147–204 change font behavior; lines 215–430 install layout/Artboard policies; lines 448 onward install text wrapping and decorations. `src/main.rs` writes `.requirements.json`; `src/wasm.rs` and `js/index.d.mts` expose the same policy result.

The baseline source was inspected with `git show 6c7ac166:PATH`, rather than assuming current source describes the old runtime. Relevant baseline files under `crates/nuxie-runtime/src/mechanical_port/source/` are `layout_component.rs`, `layout/layout_component_style.rs`, `shapes/paint/linear_gradient.rs` and `shapes/paint/radial_gradient.rs`. In the baseline, LayoutComponent already constructs rounded background/clip paths, but not the new CSS pixel-bounds policy. Its layout participant code sets **both** grow and shrink from the same fraction. LayoutComponentStyle couples line alignment and item alignment through layout alignment presets. Ordinary gradient objects already exist; their existence does not establish CSS gradient interpolation, tiling or responsive endpoint semantics.

## What the current RIV actually contains without policy

`src/lib.rs` emits Backboard, Artboard, LayoutComponentStyle and LayoutComponent records; Fill/SolidColor; embedded image/font assets; Image with LayoutParticipant; Text with its own line-box layout containers, TextStylePaint, TextValueRun and paint records. `style.rs` writes widths/heights/units, min/max, padding/margins/border widths, flex basis/fraction, direction/wrap/display/alignment presets, corner fields, aspectRatio and positioned insets. CSS parsing, selector cascade, inheritance, custom-property substitution, color/relative-unit computation, text transforms, some whitespace processing and sibling emission ordering happen in the compiler and can potentially be reused.

But several features have **no corresponding paint records**: `emit_gradient_requirement` only appends a descriptor; border helpers append policies while widths remain layout properties; decoration arrays are applied later to Text; group-opacity descriptors supply isolated compositing. Source-order records do not automatically replace the Artboard paint-order override. The current emitter cannot simply serialize the same RIV and announce immutable-runtime support.

An empty capability set is a useful migration diagnostic, not a compatibility proof. A scene can depend on PR-global fixes even without requesting an occurrence policy, notably vendor/layout, font kerning, ordinary renderer numeric and image-edge changes. Conversely some restricted scenes that currently request a blanket policy may ultimately work through ordinary baseline objects. Only fresh baseline tests decide that boundary.

## Required resurrection changes

1. **Create the compiler against the reverted baseline, not a cherry-pick of the broad feature branch.** Reuse parser/cascade/assets/wire code selectively. Audit schema record/property availability against the baseline. Keep runtime/render/schema/vendor trees identical to baseline; do not restore Taffy, ICU or renderer patches through path dependencies. Current Cargo.toml points ICU casemap at a patched vendor directory; replace with an unmodified dependency or compiler-local source-offset mapping with separate tests. Compiler dependencies must not silently modify global workspace dependency resolution.
2. **Remove policy API and transport.** Replace CompileOutput with complete `riv` plus diagnostic `source_map` and optional authoring-only metadata. Remove RuntimeRequirements/RuntimeCapability/TextPolicy exports and policy validation helpers. Remove `.requirements.json` generation in main.rs, runtimeRequirements serialization in wasm.rs and JS result/types. Do not retain a rendering-consumed replacement manifest. Version the authoring/output API explicitly if necessary rather than presenting the same language contract with silently removed semantics.
3. **Rebuild admission around the immutable target.** style.rs/css.rs should still recognize unsupported CSS sufficiently to emit precise diagnostics, but `compile` must reject computed contexts that need unavailable behavior before publishing bytes. A property whitelist alone is insufficient: intrinsic sizing, percentage basis, siblings, fonts, opacity overlap and clipping depend on the tree. Start with small ordinary-object fixtures, then admit combinations only when fresh tests pass. A recognized CSS value is not a promise of support. Preserve the user's no-grid boundary.
4. **Choose a documented output model.** Responsive Rive layout and compile-time fixed-viewport layout are different contracts. The latter could compute geometry and emit ordinary shapes/text/images entirely in the compiler; it may support more CSS per viewport but would need recompilation on size change. Do not claim current resize tests cover it. The former must fit the immutable runtime's actual ordinary constraints. No choice is established by this audit; do not smuggle browser/runtime policy installation into either model.
5. **Replace probe execution.** Use a compiler-owned test executable that links the immutable public runtime APIs, imports RIV and renders without requirement loading, font shaping modes, occurrence setters, Artboard order overrides, diagnostic gradient attachments or environment-based CSS mutations. The source map may identify objects for read-only geometry reporting only. Native glyph rendering must use only an already supported baseline route, with its profile documented; patched glyph adapters are not portable evidence. The exact import path used in tests must be the real consumer path.
6. **Rebuild tests around bytes-alone behavior.** Keep parser and cascade tests that describe intentional authoring behavior; replace requirement-manifest/host rejection tests with source admission rejection tests and ordinary Rive integrity tests. Rewrite all lifecycle examples/tests that call CSS setters. Rust/CLI/WASM/JS tests should compare complete ordinary artifacts and diagnostics without policy fields. Package/types tests must prove no required sidecar. Add a test that imports output after deleting source maps and all auxiliary metadata and obtains identical images.
7. **Requalify browser evidence.** Retain historical galleries as evidence of the old modified-runtime architecture only. Capture/reference Chrome 153.0.8010.12 with the explicit reset, then run a frozen immutable toolchain against new ordinary output. Test original/clone and multiple widths only where responsive support is promised. Keep local border/gradient discontinuity gates, full-image visual inspection, negative controls and artifact hashes, but do not transfer native qualification from a renderer with different semantics. An exact full-image match may transfer an actual inspected pair after source/artifact verification; aggregate pass counts alone cannot.
8. **Protect the new boundary.** CI should reject compiler-result host policy fields, protected source/vendor changes and any test import path that invokes CSS-only runtime hooks. Build baseline consumer executables against immutable source and bind their hashes to the receipts. Keep parser/raster/layout helpers in the compiler ownership boundary. Benchmark only the ultimately qualified architecture; the previous modified-renderer performance results do not carry over.

## Delivery sequence and open questions

First restore the baseline and establish a tiny bytes-alone colored shape/image/text control set; text is not presumed passing. Then decide and document fixed-viewport versus responsive output, qualify the simplest layout/paint cases, and expand admissions with browser comparison and explicit unsupported diagnostics. Ordinary Rive gradients, clip paths, layout wrappers, positioned glyph outlines and raster fallbacks are candidate compiler lowering techniques, each with a separate proof obligation. None justifies changing immutable runtime code.

This audit does not claim that every current CSS feature can be preserved in a responsive ordinary Rive scene. It identifies where unsupported admission must be removed and where compiler-only experiments can make progress without violating the user's architecture constraint.
