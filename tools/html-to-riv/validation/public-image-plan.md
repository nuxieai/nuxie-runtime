# Public authored-image integration plan

Implement one compiler-owned asset path for static PNG, baseline/progressive JPEG, and static lossy/lossless WebP, then qualify its actual public output. The seven source formats already exercised privately justify finishing these prerequisites; private rendering results do not automatically qualify the public flex-layout pipeline. Keep runtime, renderer, schema, root workspace resolution, and host policies unchanged.

This plan was reviewed against compiler commit `bcc4a89a20dcdeb2b12808de186c688f6e734bb3`, with the subsequent parent-owned typed Image sampler writer visible. The [ordinary image source audit](ordinary-image-source-review.md) records immutable runtime mechanisms and limits.

## Public contract

Add default-empty `assets: BTreeMap<String, Asset>` to Rust `CompileInput`. Use one tagged asset variant: `Asset::Image { bytes: Vec<u8> }`. JSON for CLI and raw WASM is `{ "assets": { "logo": { "kind": "image", "bytes": [137,80,78,71] } } }` alongside existing HTML/CSS/viewport fields; the byte array in this example is illustrative, not a valid image. JavaScript accepts the same shape with `bytes: Uint8Array | readonly number[]`, explicitly copies typed arrays, and sends the ordinary JSON envelope. No new binary ABI is needed. Omitted/empty assets preserve existing box-only output. Existing Rust struct literals require a mechanical default-field migration.

`<img src="logo">` resolves the exact case-sensitive asset key after normal HTML attribute parsing. Keys such as `__proto__` must work through own-property enumeration and `Object.fromEntries`; no prototype lookup. Prefer one exact-key spelling, rather than restoring the historical optional `asset:` prefix. No fetch, path reading, URI resolution, CSS `url()`, base64 format, caller-supplied dimensions, MIME claim, or runtime setter belongs in this contract. Assets are supplied bytes; references are authoring identifiers. Missing/empty `src` or an unresolved key is a `missing-image` diagnostic.

Require named request/asset objects, known fields and `kind`, byte integers in 0…255, and deterministic duplicate-key handling. Recommended raw-JSON behavior is to reject duplicate asset names; the current plain BTreeMap alias does not implement that recommendation and the parent must explicitly resolve it before claiming strict duplicate-name rejection. JavaScript must reject null/array maps, malformed asset objects, sparse/invalid byte arrays, and getter failures through the existing structured request-error path. Preserve the owned WASM request/result-buffer lifecycle.

Parent-selected compiler limits: 256 supplied names; 16 MiB total supplied encoded bytes before deduplication; at most 8192 per axis; 16 MiB `width × height × 4` per image. Count encoded aliases before dedup so repetition cannot bypass request limits. These are authoring limits below/equal to baseline per-image limits, not promises about total process/GPU memory. Validate lengths before copying/decoding where possible; use checked arithmetic and fallible output-buffer allocation. The existing 192 MiB JSON envelope limit remains sufficient for bounded byte-array expansion, but CLI must bound input reading too if this is claimed uniformly across transports. The initial JS wrapper leaves semantic resource decisions to Rust (its Unicode key order differs from JS sorting); oversized inputs can allocate byte-array/JSON intermediates before Rust rejects them. Do not claim pre-serialization JS memory bounds without a separate tested preflight.

**Preserve artboard-local indexing.** Emitter, padding, flex, numeric descriptors, and source maps use `records.len() - 1`, object index `id + 1`, and style index `id + 2`, assuming Backboard is the only record before Artboard. Build artboard records under that convention. After descriptor extraction, splice separately prepared global ImageAsset/FileAssetContents pairs immediately after Backboard, just before `wire::encode`. This avoids altering every helper's indexing. Image `assetId` is the global file-asset vector index, not FileAsset's authored id. Add explicit decoder tests proving both index domains.

Intern exact encoded byte strings, not decoded pixels: different encodings remain different assets. Standard borrowed byte-slice BTreeMaps suffice; no hash dependency or collision policy is needed. The initial implementation iterates supplied names in BTreeMap key order and gives the first occurrence of each exact byte string a contiguous index; generated internal names (`image0`, etc.) avoid serializing source aliases. Request insertion order does not affect output. All supplied assets, including unused ones, are validated and emitted; this intentionally avoids an additional reachability pass. Adding a differently named asset can change index ordering, which is allowed; repeated use and byte-identical aliases still deduplicate. Return key→index mappings plus derived intrinsic dimensions. Do not copy/reencode/normalize accepted source bytes.

## Portable content admission using baseline libraries

The current compiler has no image decoder dependency. Reuse existing baseline libraries in the **isolated compiler manifest only**: `png = "=0.18.1"`, `image-webp = "=0.2.4"`, and a direct path dependency on `../../vendor/jpeg-decoder-0.3.2-rive-v9f`, with defaults disabled and `rive_v9f` enabled. Record the resulting compiler lockfile and prove native/WASM builds. Do not change root Cargo files or vendored code. This introduces no new library family.

Do not let `nuxie-image-codec::validate_encoded_image` alone decide admission: its pixel decoder switches between ImageIO on macOS and portable decoding on WASM, and its `jpeg-decoder` workspace patch is not inherited by the compiler's isolated workspace. Use the same portable decoders on every compiler target; native replay remains the independent ImageIO/Metal consumer. This makes compiler decisions deterministic without claiming all accepted portable inputs must match every platform decoder.

| Format | Required checks and concrete APIs |
| --- | --- |
| PNG | Exact signature; checked complete chunk framing and terminal IEND; dimensions before allocation. Start with static 8-bit RGB/RGBA source forms represented by the private corpus. Reject APNG, EXIF, ICC, gamma/chromaticity/HDR metadata, unsupported transparency/palette/depth/interlace and unqualified ancillary semantics explicitly; sRGB-only tagging needs its own control. Use `png::Decoder::new_with_options`; enable checksums and disable skipped ancillary CRC failures, then `set_limits`, `read_info`, `next_frame`, **`finish`**, and metadata reinspection. The default decoder ignores Adler32 and skips bad ancillary CRCs. `read_info` stops before first IDAT, so it alone misses later metadata. |
| JPEG | Exact SOI; bounded segment/scan framing through EOI; 8-bit baseline SOF0 or progressive SOF2 RGB modes matching initial controls. Reject other coding processes, CMYK/YCCK, non-neutral orientation/density, ICC, EXIF/XMP and unqualified Adobe metadata. `jpeg_decoder::Decoder`: `set_max_decoding_buffer_size`, `read_info`, `info`, `decode`; require exact decoded length for reported dimensions/pixel format. Recheck metadata after successful decode; `exif_data`/`xmp_data` are only reliable then. **`icc_profile()==None` does not prove absence:** malformed/duplicate ICC marker sequences also return None. Screen actual metadata marker presence, including incomplete APP2 ICC sequences. Grayscale/subsampling variants should join only with explicit qualification controls. |
| WebP | Exact RIFF/WEBP signature, full RIFF extent, checked chunk sizes/padding and consistent extended flags. Reject ANIM/ANMF, ICCP/EXIF/XMP metadata regardless of whether feature flags are set; reject invalid/inconsistent containers. `image_webp::WebPDecoder`: `set_memory_limit`, `dimensions`, `is_animated`, `icc_profile`, `exif_metadata`, `xmp_metadata`, `output_buffer_size`, then `read_image` with the exact bounded buffer size. Static VP8 lossy and VP8L lossless/alpha correspond to the initial controls. |

Container scanning is a bounded metadata/framing check around existing full decoders, not a new pixel decoder. Check metadata throughout the container, including chunks/segments after the first image data. Keep malformed data (`invalid-image`), valid but unqualified representation (`unsupported-image`), resource excess (`asset-limit`), and missing references (`missing-image`) distinct. Unknown formats are unsupported; recognized truncated/corrupt files are invalid. Do not strip profiles, rotate EXIF pixels, flatten animation, or transcode failures silently. Exact diagnostic precedence must be frozen by tests.

Verified decoder sources: [baseline JPEG API](../../../vendor/jpeg-decoder-0.3.2-rive-v9f/src/decoder.rs), lines 40–75, 163–232, 265–293; installed `png-0.18.1/src/decoder/mod.rs` lines 143–177, 192, 590 and `decoder/stream.rs` lines 468–534; installed `image-webp-0.2.4/src/decoder.rs` lines 554–591, 643–669. Historical compiler source: `git show 33a9b6af7085164fdc45afab1b9448384a813f0d:tools/html-to-riv/src/assets.rs`. Reuse its resource/metadata checks selectively; its PNG path does not finish/reinspect, lacks exact-byte interning, and its JPEG/WebP path has platform-dependent validation. Historical `lib.rs:778` derives intrinsic ratio but couples it to runtime policy; do not restore that policy path.

## Public layout must be requalified

The [Chrome reset characterization](../output/ordinary-image-source-r1/public-reset-characterization/receipt.json) records 13 cases × four viewport steps using Chrome **153.0.8010.12**, actual current reset, and the same 96×64 authored PNG. It performs DOM measurements only; no native comparison or pixel qualification. Source HTML, script, asset/reset hashes and a corrected pre-browser path-resolution error are retained beside the receipt.

| Source context | Measured image box |
| --- | --- |
| Block body; both axes auto | 96×64 |
| Public flex-column body, width 240; both axes auto | 240×160 |
| Same, `align-self:flex-start` | 96×64 |
| Public body; width 50%, height auto | 120×80 |
| 200×120 column owner; both axes auto | 200×133.328125 |
| Same; height 80px, width auto | 200×80 |
| 200×120 row owner; both axes auto | 180×120 |
| Same; width 80px, height auto | 80×120 |

Do not replace every `auto` with intrinsic pixels or apply an intrinsic ratio in every context: fixed main-axis size with cross-axis stretching can deliberately distort the content box. Preserve CSS style values and introduce intrinsic measurements/ratio only in a dedicated image lowering plan aware of parent axis, definite size, stretch, constraints, and content-box padding. The actual sibling tail must move with the resulting used main size. Private block-flow references cannot stand in for these different public sources.

Initial public admission should include only completed branches of this matrix, with remaining combinations named precisely. Intrinsic auto sizing, min/max, percentage dimensions, box-sizing/padding, automatic margins and baseline alignment must be qualified as combinations; inherited empty-box summaries are unsafe. An ordinary ratio-bearing outer owner is a candidate, not blanket proof.

For fit/position, the standard defaults are `fill` and `50% 50%`; both properties are non-inherited. Five fit keywords map to existing Image fields. Start position grammar with the explicitly tested percentage/keyword forms and diagnose unsupported lengths/edge offsets/functions until lowered. Clipping belongs at the **content box for all fits**, including oversized `none`, not only cover. The background occupies the authored box independently. These requirements follow [CSS Images 3 §§4.5–4.6](https://drafts.csswg.org/css-images-3/#the-object-fit); the Chrome parent-position control also confirmed the child default does not inherit.

The authoring schema omits Image samplerFilter even though immutable ImageBase and CoreRegistry recognize **Uint1076**. The new `Record::set_image_sampler_filter(bool)` correctly restricts this compatibility seam to Image records and existing explicit values 1 linear / 2 nearest. Preserve the failed generic-writer receipt. Test the emitted type/key/ToC against the unchanged consumer. Do not add an arbitrary raw-property setter or modify shared schema. Nearest support alone does not implement CSS `image-rendering:pixelated`, whose noninteger scaling can require two stages; leave that CSS property diagnostic until separately proved. [CSS Images 3 §5.2](https://drafts.csswg.org/css-images-3/#the-image-rendering).

## Validation and finish conditions

1. **Asset module:** all seven exact existing source files; independent metadata/framing/corruption mutations for all three containers; bytes just below/at/above every bound; decoded bombs; profile/orientation/animation rejection; metadata after image data; checksum errors; odd RIFF chunks; progressive JPEG scans; duplicate/missing image references. Assert exact emitted bytes and one pair per unique content. Keep byte-identical aliases, distinct encodings, unused valid/invalid assets and input-key-order controls.
2. **Rust/CLI/raw WASM/JS/types:** identical requests yield identical RIV/maps; malformed requests yield structured errors and no stale output. Test typed subarrays, Buffer/Uint8Array versus numeric arrays, nonmutation, output lifetime, own `__proto__` keys, throwing getters, duplicate JSON asset names and strict unknown fields. Keep omitted/empty assets compatible. Exercise success→asset failure→success through reused compiler instances. Run the actual public compiler, not just the private generator.
3. **Public native/Chrome:** compile once per authored source, then original/clone resize and restore under the exact public reset. Cover all seven formats; both row/column; natural/fixed/percentage axes; main-axis fixed with cross stretch; ratio and min/max branches; fit/position/content clipping; transparencies/backgrounds; sibling geometry and multiple assets. Bind exact source bytes, RIV/maps, frozen compiler, immutable tools, browser reset and image dimensions. Preserve the ten private candidate pixel failures and all direct controls; do not relabel them as passes.
4. **Regression/release:** freeze final CLI/WASM and retain prior public byte/map references. Box-only files should remain byte-identical; classify any changes. Full Rust/Node/TypeScript and bounded image resource checks must pass. Native geometry, pixel/ink-presence, canvas-clear checks and complete visual review qualify only their exact source/context matrix. Update SUPPORT/BACKLOG after that evidence; no runtime change is part of this delivery.
