# Preferred-axis image bound follow-ups

These private ordinary-file experiments leave the public compiler unchanged. See `image-preferred-constraints-followup-receipt.json` for frozen generator, source, compile, native, and gallery bindings. No browser dimension is used in file construction. All requests still diagnose through the frozen public seed compiler.

The original native-transfer experiment remains intact. Omitting the automatic minimum did not reliably cause a preferred minimum to rederive the automatic preferred dimension.

The first follow-up contains twelve files and 96 actual original/clone resize frames. Eight point-bound files explicitly materialize the opposite-axis point minimum and, where present, maximum from the source intrinsic ratio. Preferred conflicting minimum/maximum values are normalized before transferring bounds. This repairs all 64 geometry and presence checks. Fifty pixel checks pass; fourteen column width-derived fractional tail failures remain.

Four percentage-minimum files instead use an outer owner with the authored preferred percentage/minimum and no aspect ratio. An appended ordinary inner owner has a 100% preferred dimension and automatic ratio dimension; the Image is parented to that inner owner. This works for width in a row parent and height in a column parent, but the mirrored cross-axis cases still measure from the earlier preferred size: height 80 instead of 120 and width 180 instead of 270 in initial frames. Its 32 frames retain 16 geometry/presence passes and 14 pixel passes. This is a failed partial composition, not evidence that percentage constraints are impossible.

The second follow-up tests eight files: preferred percentage minima and conflicting percentage minima/maxima, both axes and parent directions. Preferred percentage and preferred-axis percentage bounds use the same original containing dimension. The generator therefore clamps their source coefficients, retains a percentage preferred size, and removes the already-accounted bounds. For example, width 50% with min-width 75% becomes an ordinary width 75%, remaining responsive at runtime. No input viewport is consulted. All 64 geometry/presence checks pass; 60 pixel checks pass, retaining four width-row fractional tail failures. Existing unchanged maximum-only candidates were not rerendered.

Both direct visual reviews are complete and bound by the receipt. The point-propagation/wrapper review inspected all 12 original-resolution sheets and 36 representative pairs, with 60 exact visual transfers covering 96 frames. The coefficient-clamp review inspected all eight sheets and 24 representative pairs, with 40 exact visual transfers covering 64 frames. The point-propagation and coefficient candidates visibly restore image proportions; the cross-axis inner wrappers visibly lose bottom or right-side content. All local tail pixel failures remain. Viewport clipping of wide images in both renderers does not establish offscreen paint equivalence. The evidence does not admit mixed point/percentage preferred bounds, simultaneous opposite-axis bounds, image padding, stretch, or flex sizing. Public integration also needs numeric provenance and finite-domain guards; these private recipes are not a substitute for those guards.
