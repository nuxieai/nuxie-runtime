# Longer flex clamp cascades and literal normalization

An eight-item zero-basis, equal-factor group now reproduces512 native main-size observations exactly over64 original/clone frames in all four directions. Seven items have successively increasing maximum sizes and the last has no maximum. Eight viewport samples span400,799,the adjacent binary32 values around800,801,1600,and800 again. The source-derived model reaches seven redistribution passes. The two-pass behavior of the earlier three-item corpus is therefore not an adequate general model limit.

The first model used the original requested cap literals converted directly to binary32 and predicted eight passes. It matched only8/64 native frames. This failed attempt is preserved in output/flex-freeze-cascade-r1/summary.json and the initial checks.json files. The compiler's stylesheet token serialization normalizes100.71428680419922px to100.714px, for example, so those input constants did not match the emitted file. The actual cssparser trace is retained in literal-trace.json. A separate check-serialized.py consumes the normalized token's final binary32 value; it then matches every native main size without changing or rerendering the files. Those corrected traces are in serialized-checks.json. This is evidence for including the actual parser/serialization path in the numerical model, not evidence of exact original-CSS decimal equivalence.

The compiler is the frozen private flex candidate from flex-integration-module-r6. Emitted files contain ordinary native properties only. All probes use the immutable baseline, and no source/runtime mutation or public admission was performed. Pass counts are inferred by the audited source simulator; the native runtime was not instrumented. Matching final sizes does not uniquely identify internal native traces.

For finite intermediate values, the native loop freezes at least one previously active item per iteration: a positive total violation requires at least one positive violation, a negative total requires a negative one, and zero freezes all active items. Thus at mostN iterations follow initialization forN participants. This is a source argument, not a proof that arithmetic is finite, that a lower pass cap is safe, or that total scene cost is acceptable. Each pass rescans the line and collects active items, so a conservative group work bound is quadratic in participant count. Error bounds must follow changing active sets and rounded total-violation decisions instead of assuming fixed two-pass behavior.

No Chrome/pixel run, continuous-domain bound or public flex support is added by this checkpoint. The earlier fractional paint failures remain. Next work is to connect verified literal metadata and production descriptors to bounded iterative arithmetic.
