# Exact script-signature verification on host-free WASM

This adapter preserves libhydrogen's signature format and algorithms. It is not
Ed25519, and it never substitutes an accept/reject policy for verification.
Callers still own header parsing, signature length checks, context, keys, and
admission. Native builds delegate to the unchanged `libhydrogen = 0.4.6` crate.

`wasm32-unknown-unknown` could not build `libhydrogen-sys = 0.9.4`: its combined
translation unit requires hosted C headers and a platform RNG. The runtime only
needs verification, which uses neither the RNG nor a hosted C environment.
`c/verify.c` includes the exact hash, Gimli, Curve25519, and signature sources,
namespacing public symbols for differential tests. It does not include the RNG
or core translation units. Unreferenced signing/keygen functions from the
original headers are removed by section garbage collection. No RNG definition,
dummy initialization, WASI, or Emscripten is supplied. A dependency on any omitted
function must fail linking or the required zero-import test.

The three freestanding headers contain declarations only. Integer and size
types come from Clang's target headers; any non-inlined memory primitive resolves
to Rust's compiler-builtins. No C allocator, operating-system service, or ambient
entropy source is linked. Build with a WebAssembly-capable LLVM Clang. Explicit
cc-rs target `CC`/`AR` settings are respected; otherwise `llvm-config --bindir`
(or `LLVM_CONFIG_PATH`) selects Clang and llvm-ar, avoiding Apple's native-only
Clang. This changes build tooling only, never the target away from
`wasm32-unknown-unknown`.
Use `LLVM_CONFIG_PATH` or target `CC`/`AR` settings to intentionally switch
toolchains. Build caching tracks those settings and the selected LLVM tool
files, not unrelated per-invocation `PATH` entries added by package managers.

## Source provenance

All files in `c/upstream/` are byte-identical copies from the locked
`libhydrogen-sys 0.9.4` package. Package SHA-256:
`775d7d3bdc46473090d1845fe81ea7e86db697d0a67c72684778446242a05237`.
Its source commit is
[`8f7c386f06f3c915bb07b8e457db39d6d1f52abe`](https://github.com/jedisct1/rust-libhydrogen-sys/tree/8f7c386f06f3c915bb07b8e457db39d6d1f52abe),

[`576a38bfd14357326a9727f977b46014363eeec8`](https://github.com/jedisct1/libhydrogen/tree/576a38bfd14357326a9727f977b46014363eeec8).
`c/upstream.sha256` records every copied file, including the original license;
the build script rejects any changed bytes. No cryptographic source edits exist.

## Qualification

Run native differential tests (pin `RUSTC`/`RUSTDOC` to the intended rustup
toolchain if a system Rust installation shadows it):

```sh
cargo test -p nuxie-script-signature --features freestanding-tests
node tools/test-script-signature-wasm.mjs
```

Both compare against signatures generated by the original native library,
covering two contexts and eleven message lengths (including empty and block
boundaries). Each valid case is followed by all 64 individual signature-byte
mutations, changed message/context/key, and a zero signature. The Node test
instantiates a real release WASM artifact, requires zero imports, invokes the
Rust-selected backend through a test-only example ABI, and checks 1,518 cases.
Audit final publisher/ProductHost artifacts for unintended libhydrogen, RNG,
WASI, or other ambient-host imports too. ProductHost's ordinary wasm-bindgen
and browser imports remain allowed; the isolated verifier has zero imports.
