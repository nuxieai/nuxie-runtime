# Shared page player

`nuxie_runtime::page_player`, also exported as `nuxie::page_player`, owns the frame order for published pages. The C API calls this implementation. Preview can use it through ProductHost without reproducing the C frame loop.

## Entry points and ownership

Keep a `PagePlayer` alongside an `ArtboardInstance` and its `Playback`. Pass bound and global view-model roots as subscriptions. For a scripted import, pass its `ScriptedFile` as `Effects`; that integration owns the script checkpoint and command drain.

- `step` accepts indexed inputs, pointers, focus inputs and elapsed seconds. Its owned `Output` contains events, view-model changes, host commands, input results, state changes and scheduling flags.
- `step_begin`, `step_end` and `set_row_collapsed` use the same transaction and failure boundary. `None` is the Rust spelling of a C NULL-name cut. Commands generated by status operations are deferred to the next ordinary step.
- `operation` is the staged form used by the C adapter. Its `PendingStep` keeps the frame scope, transaction, host rule scope and occurrence guard alive while the adapter publishes its ABI result. Dropping an uncommitted mutated operation rolls values back and poisons the occurrence. C handle validation, caller-memory conversion and ABI size checks remain in the adapter.
- `content_height` returns the top expanded Screen's intrinsic height in points after a step. C exposes the same query as `nux_player_content_height(player, &height)`.

The shared operation owns frame scope, eager or lazy checkpoint, input dispatch, advance, live-move follow, event ownership, script effects, value-policy resolution and subscription filtering. Native occurrence state prevents reentry and retains terminal failure across different player wrappers. Ordinary preflight refusals remain recoverable.

## Page shape and row ordering

The existing one-time root capability decision now accepts `$nuxie.page` with a `screens` component list even without records. Legacy roots with LiveStep records remain supported. A record-free ordinary root keeps its negative decision and allocates no live-move scene state.

Begin, end and row sleep first flush pending binding changes and settle component updates without advancing playback. Insertions, removals and moves therefore take effect before row lookup and ownership transfer. This also settles the fresh incoming row's opacity and transforms before flight validation.

The host controls stack order through the view-model list. Move the incoming row just above the outgoing row for forward navigation and just below it for back navigation, then call begin in the same batch. List moves retain row instance identity, playback, view model and sleep state. The player does not clone or recreate a kept row.

## Content measurement

After the ordinary step settles layout, the query selects the last active Screen in list order. It copies only that Screen's subtree from the persistent Taffy tree and measures it with the runtime's existing solver and leaf measurement callback, at the page width with unconstrained height. It never publishes the scratch layout, advances playback or drains events.

The owning layout tree caches one answer by Screen node and width. Repeated queries reuse it; the next normal layout solve invalidates it. The first query after a relevant solve costs one intrinsic subtree solve, so this is not a second implementation of layout and is not a zero-work query on a changed frame. Sleeping rows and other Screens are not measured.

Scripted layout uses its last natural measurement from the ordinary layout pass. The query never executes script callbacks. It returns an error if a settled Screen layout tree or required natural measurement is unavailable. An empty expanded stack returns NotFound. Callers should query after stepping, including after changing page width or bound text.
