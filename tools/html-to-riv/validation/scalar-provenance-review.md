# Bounded computed scalar provenance

The registered private scalar_provenance module pairs an actual finite native binary32 value with outward binary64 bounds on its original mathematical value. Missing original text is an explicit error. Compiler-defined exact constants have a separate constructor; normalized native floats cannot silently replace missing ideals.

Decimal scanning retains18 significant digits for an enclosure and at most128 canonical digits for equality identity. Discarded nonzero tails widen the prefix interval; exponent scanning saturates relative to input length. Scaling is bounded and outward-rounded, preserving tiny nonzero values as signed intervals containing zero without classifying them as exact zero. Large unbounded ideals diagnose. Memory used by retained decimal/equality data is bounded independently of token length; input scanning itself is linear in token length.

Ideal equality requires canonical exact identity or a shared computed-expression identity. Equal rounded floats or overlapping intervals are insufficient. Independently computed complex expressions can remain equality-unresolved. Arithmetic keeps each native operation order: ordinary multiplication for em/rem; divide100 then multiply for font percentages/padding coefficients; multiply owner then0.01f for preferred dimensions. Concrete-owner percentage methods are not whole-viewport proofs; dynamic containing-block envelopes remain separate work.

Every ideal interval operation rounds outward. Invalid intervals/divisors and nonfinite native operations return explicit errors; direct error estimates for nonfinite inputs return infinity. A first native overflow cannot be hidden by the later0.01 multiplication. These methods calculate metadata; they neither mutate runtime values nor admit compiler semantics.
