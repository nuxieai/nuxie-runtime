# Differential corpus for nuxie-luau-vm

Each `*.luau` file is one case. `make luau-vm-diff` compiles it with the
vendored compiler under three profiles (all flags on at -O1 and -O2, all flags
off at -O1), runs the same bytecode on the vendored VM and on
`nuxie-luau-vm`, and compares returned values, `print` output and the escaping
error. Add a case by adding a file. A case whose first line is
`-- luau-vm-diff: flags-on` runs only under the profiles with the flags on
(for flag-gated syntax such as `1i` integer literals).

Cases must be deterministic on both VMs: never print an object address and
never depend on the iteration order of a table's hash part (sort keys first).
The harness provides `print` and `loadstring(source [, name])`.

After the run the harness checks that the corpus reached every opcode the
loader admits.

`fastcall_*.luau` (but for `fastcall_rebind.luau`) are generated by
`tools/luau-vm-diff/gen_fastcall_cases.py`; change the generator and rerun
it rather than editing them. A case must not name `getfenv` or `setfenv`
directly where it wants builtin calls compiled: the compiler then emits no
`FASTCALL` for the whole script.

`pairs_order_gen_*.luau` are generated by
`tools/luau-vm-diff/gen_pairs_order_cases.py` (fixed seed) and, with
`pairs_order_*.luau`, are the exception to the hash-order rule above: they
print hash-part iteration order on purpose, because the safe VM matches the
vendored VM's order for string, number, boolean and vector keys
(`docs/luau-safe-vm-pairs-order.md`). Each generated table prints lines
labelled `T<file>.<n>.<step>`; `tools/luau-vm-diff/count_pairs_order.py`
counts disagreeing tables from a `--verbose` run.
