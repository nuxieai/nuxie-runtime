# Resource campaign integration review

The completed 40-case campaign supports marking Q06 **partial**, with 120 interface observations around three authoring limits: combined UTF-8 source length, authored nesting and authored element count. Its complete requests, expectations, calls, recorded outputs and independent verifier were reviewed before adding the evidence to the shared progress documents. No compiler defect or reason to rerun the unchanged campaign was found.

One sentence in the original review needs a narrower interpretation. The worker checks zero output lengths after raw ABI allocation, but it explicitly resets after each compile. It therefore does **not** independently exercise allocation clearing a still-live previous raw ABI response. Its demonstrated lifecycle checks are zero post-allocation lengths, no Rive output after rejection, reset clearing lengths, exact repeats and recovery. Native retained-file checks and public JS output-ownership checks do exercise preceding successful results across failures. The earlier malformed-transport campaign owns separate raw ABI lifecycle evidence.

The verifier checks all 530 recorded case artifacts, all 134 frozen compiler bindings, regenerated request identity, byte/scalar counts, complete response parity, exact CLI repeat/no-op/recovery files, authored IDs/paths and retained output content. Its full-campaign counts are intentional; it is not a verifier for a `--only` replay. Raw ABI metadata is copied before reset, and the campaign does not promise continued access to compiler-owned raw buffers. Worker/process limits are harness bounds, not measured compiler memory ceilings or a throughput contract.

Source-size pressure is inert-comment padding, not expansion-heavy CSS. Structural cases use fixed-size plain and content-box boxes in nested, flat and two-group arrangements. The six combined-limit controls cover the documented source-before-structure precedence. This does not cover all limit interactions, the admitted 192 MiB request maximum, viewport/numeric/selector/variable limits, arbitrary host pointers, coverage-guided fuzzing, cross-host execution or browser/native rendering. No new language support or rendering qualification is claimed.

The original review, aggregate receipt, frozen inputs and campaign/verifier receipts remain unchanged. This note qualifies the single lifecycle wording issue while preserving their hashes. Integration updates `SUPPORT.md`, `VALIDATION.md`, the Q06 row in `BACKLOG.md`, and `validation/progress-state.json`; `validation/progress-page.py` regenerates the progress webpage.
