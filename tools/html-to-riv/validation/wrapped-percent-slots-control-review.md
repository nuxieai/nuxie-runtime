# Percentage-slot translation omission control

The eight 120×120 fractional center/bounds failures remain when the final TranslationConstraints on visible items a/b/c are omitted. All eight control native images are exactly identical to the constrained candidate's decoded RGBA pixels; Chrome disagreement persists. This excludes those final visible-item translations as the source of these eight failures. It does not isolate native layout rounding from rasterization or other retained slot/composition behavior.

The control takes the four failing row/column × wrap/wrap-reverse center-bounds scenes from `output/wrapped-percent-slots-r1`. Its sole Rust change replaces `b.copy(ids[i+4],target,1.,false,false)` with an unused-target statement. Percentage slots, percentage sizing, all intermediate constraint graphs, paints, layout alignment, and native wrapping remain. Authored inputs and adapter are copied exactly, with the case collection narrowed to four scenes. No public compiler or runtime source changes are involved.

Each ordinary file was imported once, resized through the original four viewports, and replayed on a clone. At frames 2 and 6 the 120×120 viewport separates all three items into distinct lines, so the intended alignment offsets are zero. All eight target geometry checks pass, all eight pixel checks fail, and constrained/control native pixels match exactly. The larger viewports require nonzero offsets: omitting them deliberately breaks whole-case parity. Full control totals are 4 scenes, 32 frames, 8 geometry passes, 0 pixel passes, and 64 clear checks. The driver's failed exit status is preserved and expected; none of these scenes are qualified or publicly admitted.

`output/wrapped-percent-slots-control-r1/comparison.png` contains four directly reviewed triplets: Chrome, original constrained native, and omission control. The native pair is indistinguishable in each row; Chrome disagreement remains around fractional boundaries. Frame 6 for each case is an exact decoded-RGBA transfer from its frame-2 triplet, verified separately for Chrome and native. Other 24 frames received automated validation only. The original-versus-control eight-frame equality proof is in `comparison.json`.

`src/main.rs`, `src/wire.rs`, `adapter.py`, fixture inputs, actual `build-command.json`, linked source hashes, `render-command.json`, raw logs and receipt are preserved under the output directory. `freeze.py` checks source/tool bindings and reproduces all four complete adapter results: identical RIV bytes and equal parsed maps. `experiment-manifest.json` binds this artifact set and the original candidate's receipt and target native images. Chrome is pinned to 153.0.8010.12 and the immutable Rust Metal RasterOrdering renderer is used. The first setup command inadvertently rebuilt the unchanged original augmenter before correcting its relative output path; its bytes were verified identical to the original build receipt before the control ran.

The conclusion is limited to these target frames and retained composition. A bare-layout or raster-edge diagnostic would be needed to identify the remaining cause precisely; no runtime modification is justified by this control.
