# Computed flex descriptor extraction seam

The compiler now provides a private `compile_profile_with_descriptors(input, policy)` entry returning the ordinary `CompileOutput` plus serializable group descriptors. Public compilation and the existing candidate entry retain their signatures, admission gates and byte outputs; descriptor collection is opt-in. No numerical model is invoked and every descriptor states `numerical_admission: false`.

`src/flex_descriptor.rs` extracts compact scalar facts directly from each computed Style and the emitted authored/outer participant handles. It retains source identities, DOM indices, CSS order, logical item order, actual native participant file order, native main/cross scales, stored length/unit fields, and native linked grow/shrink. Authored shrink remains separate: a computed shrink of 7 can correctly coexist with a serialized native shrink of .25 when the candidate uses the zero-basis mapping. Legacy fixed siblings retain their serialized preferred point dimensions; absent basis/min/max fields remain absent in the raw record facts rather than receiving invented CSS ideals.

The capture records compact pending parent/item facts, not complete Styles or their inherited variable environments. Final topology checks run after all ancestor baseline helpers have been emitted. A single constraint-owner index identifies affected participants/parents; each group's bounded record range identifies direct native children and unaccounted-for helpers. The descriptor flags helpers, alignment wrappers, parent spacing/padding, item margins/padding, intrinsic or responsive basis/bounds, and unqualified cross sizing. It includes groups beyond flex-enabled children so a future caller can examine surrounding topology.

This is fact extraction, not the full structural model contract. Exact authored literal provenance, parent-size error, ancestor-world error, native default transform provenance and descendant target preservation remain explicit missing premises. In particular, computed binary32 values cannot recover original CSS decimal ideals after token serialization, variable substitution or font-relative calculation. No missing error becomes zero, and an empty structural-issue list does not mean the numerical model may admit a group.

The model contract was coordinated with the independent `flex-literal-descriptor-r3` checker. An adapter must supply the missing exact ideal/native provenance and ancestor error metadata before constructing its analysis input; this module intentionally does not duplicate that checker or infer descriptor facts from fixture names.

Validation: `cargo test --locked` passed 155 tests, recorded in `output/flex-descriptor-tests-r3.log`. Three new tests run the actual compiler pipeline and verify all four direction/order mappings, source identities and serialized factors, unchanged candidate bytes/maps with capture enabled, explicit wrapper/spacing-helper detection, null unresolved metadata, and detection of ancestor-added baseline constraints after complete emission. No new native/browser or pixel qualification is claimed. Runtime sources and public nonlegacy-flex admission are unchanged.

The crate-root harness initially exposed an inaccessible return type: Group was visible only inside compiler while the capture function was visible to its parent. The source now gives serialized descriptor types crate visibility, preserving the private compiler interface. Failed setup logs are retained in flex-descriptor-module-r1/r2; the first was a missing serde extern in the harness, the second the source visibility issue.
