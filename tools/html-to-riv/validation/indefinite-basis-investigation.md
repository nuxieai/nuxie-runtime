## Specification check and runtime hypothesis

Checked the [14 October2025 Flexbox draft, section7.2.3](https://www.w3.org/TR/2025/CRD-css-flexbox-1-20251014/#flex-basis-property): an unresolved percentage basis uses content sizing. By contrast, auto first consults the authored main-size property. [Section9.8](https://www.w3.org/TR/2025/CRD-css-flexbox-1-20251014/#definite-sizes) also defines post-flex sizing cases that establish definiteness. Therefore a simple percentage-to-auto rewrite risks incorrect fixed-dimension behavior and nested resolution.

Local source hypothesis: Taffy's flex-basis calculation calls maybe_resolve, then uses flex_basis.or(main_size). An unresolved percentage and Auto both become None, which may incorrectly select a fixed authored main size. This is a suspected mismatch, not yet a reproduced failure. The25-case baseline includes fixed/auto dimension pairs to distinguish it. Preserve initial results before changing the engine.
