# Receiving-property grammar audit for nonempty variable recovery

The safe boundary is the receiving property's CSS grammar, before immutable-target admission. Recover only a value proven invalid after successful ordinary `var()` substitution; retain its name, source, importance and cascade position, replacing its effective value with `unset`. An invalid winning declaration must not expose an earlier declaration. Custom-property values are data until used by a receiving property; CSS-wide custom values instead participate in their own cascade. [CSS Variables](https://drafts.csswg.org/css-variables-1/#using-variables), [CSS Cascade defaulting](https://drafts.csswg.org/css-cascade-5/#defaulting).

This audit uses the existing 476-form Chrome153 corpus and 118 additional probes. It changes no production source or public admission. The primary CSS editor drafts below were consulted on 2026-09-12 and are work in progress; pinned browser behavior and normative grammar are recorded separately. Native validation still awaits a frozen compiler.

## Grammar partition

All 33 admitted receiving names fall into the following groups. A recognized CSS production does not imply native support, supported units/context, resource safety, or support for every keyword below.

| Receiving names | Conservative primitive grammar | Values that must retain target diagnostics |
| --- | --- | --- |
| `width`, `height`, `min-width`, `min-height` | One nonnegative length/percentage or sizing keyword; `auto` is legal; `none` is not | Intrinsic sizing, `stretch`, unsupported length units and opaque sizing functions |
| `max-width`, `max-height` | Same nonnegative size domain, with `none` replacing `auto` | Same unsupported sizing/context cases |
| `font-size` | One nonnegative length/percentage, absolute/relative font keyword, or extension recognized by its defining module | `large`, `xxx-large`, `larger`, `math`; percentage is already admitted |
| `box-sizing` | One of `content-box` / `border-box` | Existing unsupported content-box contexts |
| `color`, `background-color` | One color production | System colors, vendor colors, newer/opaque color functions |
| `background` | A layered shorthand; a lone color is only one valid form | `20px`, `-20px`, `0`, repeat/box keywords, position/size, image functions and multi-layer forms |
| `display` | One legacy keyword or valid combined outside/inside/list-item production | `block flex`, `flex block`, `inline flow-root`, list-item combinations, grid, math, table/ruby forms |
| `flex-direction` | One of row, row-reverse, column, column-reverse | Existing target/context diagnostics |
| `flex-grow`, `flex-shrink` | One nonnegative number | Valid nonlegacy factors and initial shrink 1 |
| `flex-basis` | One nonnegative width-like value, additionally `content` | Content/intrinsic basis, unsupported units/functions |
| `flex` | `none`, or ordered optional grow/shrink pair combined with basis | Nonlegacy factors/bases; valid alternate basis placement |
| `order` | One lexically integral number token | Integers beyond target signed-32-bit bounds |
| `align-self`, `justify-content` | Their separate positional, distribution, overflow and baseline productions | Unsupported alignment combinations and extensions |
| `margin`, four physical longhands | One to four components for shorthand, one for a longhand; signed length/percentage or `auto` | Negative/nonzero/percentage margins remain valid CSS |
| `padding`, four physical longhands | One to four nonnegative length/percentage components; one for longhands | Unsupported units/context; negative literals are invalid |
| `gap`, `row-gap`, `column-gap` | One or two nonnegative length/percentage/`normal` components for gap; one for longhands | Unsupported context/functions; `normal 1px` is valid |

Sources for the partition: [Sizing3](https://drafts.csswg.org/css-sizing-3/#sizing-properties), [Fonts4](https://drafts.csswg.org/css-fonts-4/#font-size-prop), [Backgrounds3](https://drafts.csswg.org/css-backgrounds-3/#background), [Display3](https://drafts.csswg.org/css-display-3/#the-display-properties), [Flexbox1](https://drafts.csswg.org/css-flexbox-1/#flex-property), [Alignment3](https://drafts.csswg.org/css-align-3/#overview), [Box3](https://drafts.csswg.org/css-box-3/#margins), [Values4 integers](https://drafts.csswg.org/css-values-4/#integers).

Strings and bracket blocks at the top receiving level, proven wrong primitive types, prohibited known-unit negative values, invalid complete cardinality, and a CSS-wide keyword combined with other components are bounded recovery opportunities. Keep functions/opaque syntax unclassified. A nested quoted URL is not a top-level string. Preserve token kind and boundaries: an escaped identifier containing spaces remains one identifier, while CSS comments separate tokens. CSS whitespace excludes NBSP, vertical tab and em-space; non-ASCII characters remain valid in custom-property names/data. [CSS Syntax tokenization](https://drafts.csswg.org/css-syntax-3/#tokenization), [Values4 value definitions](https://drafts.csswg.org/css-values-4/#value-defs).

## Concrete pitfalls and controls

1. **`revert-rule` must not become an invalid unknown identifier.** Current Cascade5 defines this additional CSS-wide keyword, and Chrome153 accepts it. Preserve the diagnostic for direct ordinary use, ordinary fallback use, and custom-property declarations. `variables.rs` historically rejected only `revert`/`revert-layer`; treating `--v:revert-rule` as ordinary data is also wrong. A standalone custom value can disappear or roll back an earlier rule before `var()` selection. Combined `revert-rule 1px` is distinct from the standalone keyword. [Cascade5](https://drafts.csswg.org/css-cascade-5/#revert-rule-keyword).

2. **f32 zero/sign is insufficient for grammar classification.** In standards-mode Chrome, `width:1e-50` and `width:-1e-50px` are invalid; the direct declaration preserves earlier width40px. Chrome accepts `1e-500` and `-1e-500px` as zero after underflow, as well as actual `-0px`, `-0.0px`, `0e0`, and `0.0`. A cssparser f32 payload collapses the first two problematic values too early. Retain the authored numeric coefficient for classification. The meaning of invalidity, representable range and target limits must remain separate; Chrome also accepts `1e999px`, whereas the compiler intentionally diagnoses its nonfinite token. These are exact observations in `grammar-probes-r2/receipt.json`, not a claim of an exact arbitrary-precision CSS implementation.

3. **Literal integers depend on spelling.** Chrome rejects `order:1.0` and `order:1e0`, while accepting `-0`, `+0001`, and values beyond 32-bit bounds. The last group needs a target/resource diagnostic, not recovery. The spec's literal integer form is decimal digits with optional sign; numeric rounding equivalence does not change token grammar. [Values4 integers](https://drafts.csswg.org/css-values-4/#integers).

4. **A failed solid-color parser cannot classify `background`.** Chrome accepts `background:20px`, `-20px`, `0 0`, `border-box padding-box` and `center/cover`. They set background subproperties even without a color or image. A primitive classifier can leave complex shorthand sequences unclassified rather than infer their grammar from the current solid-color lowering. `background-color:20px` is a useful separate wrong-type control. [Backgrounds3 shorthand](https://drafts.csswg.org/css-backgrounds-3/#background).

5. **Flex grouping is ordered.** Chrome accepts `auto 0 0`, `1px 0` and `0 1px`, but rejects `0 auto 0` and `none 0`. Allowing an arbitrary permutation of three individually recognized components is incorrect. Escaped `\30 \20 \30 \20 auto` remains one identifier, not the valid `0 0 auto` sequence. Keep factor and basis admission separate from grammar. [Flexbox1 flex](https://drafts.csswg.org/css-flexbox-1/#flex-property).

6. **Modern extensions need explicit preservation.** Chrome accepts `align-self:anchor-center`, `display:math`, `font-size:math`, and sizes `stretch`/`fit-content`. The length controls `10vi`, `10cqw`, `10rex`, `10cap`, `10rcap`, and `10rlh` also parse. Omission from a target whitelist does not prove invalidity. `anchor-center` is added by another module, outside Alignment3's original production. [Anchor Positioning](https://drafts.csswg.org/css-anchor-position-1/#anchor-center), [Sizing3](https://drafts.csswg.org/css-sizing-3/#sizing-values), [Values4 lengths](https://drafts.csswg.org/css-values-4/#lengths). The `math` assertions here are pinned Chrome observations rather than a full MathML implementation proposal.

7. **Draft/browser disagreement should remain unresolved.** Current Alignment3 permits overflow-prefixed `normal` for `align-self`, but Chrome153 rejects `safe normal` and `unsafe normal`. `display:run-in` is specified but also rejected by this browser. Treating such values as unclassified keeps the target diagnostic and avoids presenting browser nonimplementation as normative grammar invalidity. Chrome accepts `first baseline` / `last baseline`, rejects `baseline first`, and only permits relevant overflow prefixes. [Alignment3 align-self](https://drafts.csswg.org/css-align-3/#align-self-property), [Display3](https://drafts.csswg.org/css-display-3/#the-display-properties).

8. **Function behavior remains outside this primitive checkpoint.** `width:calc(-20px)` is valid CSS and computes to zero, while literal `-20px` is invalid. `light-dark(red,blue)` is a valid newer color function. An unknown function's failure in the target parser must remain diagnostic; recovery must not hide syntax errors, nonfinite tokens or expansion limits. This boundary intentionally leaves some browser-invalid opaque functions unrecovered. [Values4 calculations](https://drafts.csswg.org/css-values-4/#calc-range).

9. **New background clip keywords also apply to the shorthand.** Chrome153 accepts both `background:text` and `background:border-area`; classifying unknown background identifiers through only a color parser would incorrectly recover them. Backgrounds4 adds these clip values. Both must retain target diagnostics, with direct and variable controls. These two observations extend the additional probe matrix from 116 to 118. [Backgrounds4](https://drafts.csswg.org/css-backgrounds-4/#background-clip).

## Source review after the repairs

The parent's current classifier retains all complete token components, reads numeric coefficients as f64 before the target's f32 narrowing, includes `revert-rule`, preserves modern background clip and other unsupported keywords, and leaves the `safe normal` disagreement unclassified. The shared style/order substitution helper completes resolution before deciding recovery, so syntax/nonfinite/resource errors are returned before classification. The synthetic `unset` retains the existing declaration's provenance and cascade priority. A separate literal validity guard runs after target parsing so permissive f32 zero rounding cannot silently admit known-invalid literal values. This review introduces no production edits.

The private source-snapshot observer in `classifier-audit-r2/` compares all 594 Chrome rows. It finds no `Invalid` result for a Chrome-supported value. Four `Valid` results correspond to browser-rejected draft productions: `contain` on width/min-width/max-width and `display:run-in`. They retain target diagnostics; they are not support claims. The observer examines only the grammar function and cannot qualify public transport, resources, native output or every CSS production. Source snapshots and dependency hashes are preserved in its receipt.
