## Commit evidence and port boundaries

### S5-2 — text style backgrounds

`dev/defs/text/text_style_background.json` adds runtime type key 1069 and
bindable/animatable `cornerRadius` key 1071. The runtime constructs an even-odd
joined `TextSelectionPath` from shaped glyph bounds, draws it before glyphs,
propagates opacity, and invalidates paint when the radius changes
(`src/text/text.cpp`, `src/text/text_style_background.cpp`). Nuxie already owns
the corresponding text, selection-path, shape-paint-container, and draw
surfaces. The new `.riv` fixture and focused contour/runtime tests should land
with the schema/runtime port.

### S5-3 — path-effect clipping

`src/shapes/clipping_shape.cpp` now reads each fill's post-effect path, falls
back to composed geometry only for unaffected fills, sorts after effected
fills, and ignores stroke centerlines. `src/shapes/paint/shape_paint.cpp`
recursively propagates path dirt so clips rebuild after effect invalidation.
The existing direct Rust clipping owner is
`crates/nuxie-runtime/src/shapes/clipping_shape.rs`; this is a high-risk dirt
and dependency-order change despite its compact diff. Enroll
`scripted_path_effect_clip.riv` in the scripted corpus.

### S5-4 — library TextInput

The authored `artboardKind` and `previewAnimationId` additions in
`dev/defs/artboard.json` are runtime-false editor metadata. The runtime hunk in
`src/text/text_input.cpp` is still material: library instancing may enter
update before a style is attached, and a later style must refresh both font
and font size. Nuxie's TextInput surface is closed and directly owned, so this
is a runtime PORT with an editor-metadata schema regeneration rather than a
whole-commit skip.

### S5-5 — IK stale FK base

`src/constraints/ik_constraint.cpp` stops decomposing a potentially stale
world transform. It first updates the bone's local transform, reconstructs the
current world transform from the parent, and decomposes the local transform as
the FK base. This is localized but touches float/transform/constraint order;
the new multi-frame `ik_anim_test.riv` fixture is required evidence.

### S5-6 — deferred renderer sessions

The new `renderer/.../cmd` family records and replays 2D and ORE resources,
groups offscreen canvas work before screen targets, topologically orders
canvas sampling, detects cycles/multi-write fallbacks, and retains per-frame
foreign-image/resource identity. `Factory::renderContext()` and
`deferredCanvasHost()` route scripting through the import factory;
`Artboard::instance(Factory*)` reinstances nested artboards on the override
factory. The change also removes the old scripted `drawCanvas` callback while
adding orphan-frame cleanup and late-bound GPU-canvas sizing.

Those semantics overlap Nuxie's GPU-canvas and recording seams, but the native
ORE/GL session implementation is not portable verbatim. Before PORT approval,
split an adaptation map into: import/instance factory routing; GPU-canvas frame
lifetime and error unwind; multi-target/canvas dependency scheduling;
resource identity/teardown; and native-backend-only exclusions.

### S5-7 — color-channel passthrough

`dev/defs/shapes/paint/color_channels.json` generates shared uint property keys
118/136/210/218 over the existing packed ARGB `colorValue` in `SolidColor` and
`GradientStop`. `src/data_bind/context/context_target_value.cpp` preserves a
number source as `DataValueNumber` when reading a uint target;
`src/data_bind/data_bind.cpp` makes the four derived channels one-way targets;
`src/shapes/paint/gradient_stop.cpp` tolerates detached stops. These are active
schema, data-binding, and paint owners and should land with
`color_passthrough_test.riv`.
