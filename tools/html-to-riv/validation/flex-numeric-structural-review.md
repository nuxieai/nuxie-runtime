# Structural flex arithmetic and final-placement model

The executable prototype in `output/flex-numeric-admission-r2` closes the final-placement operation gap for the two previously modeled single-pass profiles, and accepts structural descriptors rather than fixture names. It remains an experimental numerical analysis API, not a public admission guard. The model compares native binary32 arithmetic to exact arithmetic on the same serialized constants; it does not establish browser semantic or pixel equivalence.

## Parent-input premise correction

The r2 numerical results below are **conditional on the supplied parent error, which has not been established over the complete viewport domain**. The fixture descriptor assumed a 50% parent needed only a single multiplication's rounding allowance. The immutable preferred-size path actually computes `fl(fl(percent * owner) * 0.01f)` (`vendor/taffy-0.12.1-rive-yoga-order/src/util/resolve.rs:39`). Both operation roundings and the binary32 representation of 0.01 must enter the parent error. Consequently r2 does not establish whole-viewport admission for these eight scenes. Its model operation trace and retained-frame comparisons remain useful; corrected parent/literal metadata requires separate r3 evidence. Percentage padding uses a different divide-then-multiply path and must not reuse the preferred-size formula.

The original review is preserved as `output/flex-numeric-admission-r2/review-original-conditional.md` so r2's historical evidence remains inspectable.

## Conditional results

Using r2's unproved parent-error premise across the complete viewport main domain `(0,16384]`, the parent's 50% main interval is enclosed by `[0,8192]` plus a conservative input-conversion error. Eight of the original 24 cases pass the model under that premise; these are not qualified whole-domain bounds:

| Profile | CSS ordinary direction, either axis | CSS reverse direction, either axis |
| --- | ---: | ---: |
| equal-partial | 0.004187943 px | 0.010492805 px |
| zero-unequal | 0.006814482 px | 0.013806030 px |

These are upper bounds on maximum main size/world-position arithmetic error, not measured browser differences. The same API also accepts five independently specified shapes: four partial-factor items in ordinary/reverse directions, five participants with unequal zero-basis factors and fixed siblings, one zero-basis item, and point min/max bounds with provable slack. Their maximum bound is 0.030989663 px. None of those additional shapes has a new native/browser run in this evidence.

The runner checks 512 main size/position comparisons against all 64 retained original/clone frames for the eight covered corpus scenes. Every observation fits its bound; maximum observed error against the exact reference is 0.000005086263021 px. It additionally checks their rigid world matrices, exact cross-axis origins, and fixed cross sizes. These are checks of the model implementation against previously captured native geometry, not a new native replay or a sampling-based whole-domain proof.

All sixteen original freeze-dependent cases remain unresolved: equal-basic, equal-clamped, zero-partial, and zero-minimum in four directions. The extra controls diagnose the 8192-item mixed-factor uncertainty, the equal-basic zero-clamp issue, an unproved transform contract, and a nonfinite resolved ancestor bound. Failed/uncertain cases are not removed or counted as supported.

## Structural API and required caller proof

`analyze(group)` consumes definite parent `[lo,hi]` plus its absolute error; optional parent world-translation range/error; an ordered list of serialized binary32 `basis`, `grow`, `shrink`, point `min`, optional point `max`; logical reversal; and a requested geometry error budget. Fixed siblings use both factors zero. It emits bounded per-item intervals/errors or an explicit unresolved reason. No fixture name enters the function. Exact `Fraction` arithmetic prevents rounding in the bound evaluator; its outward float reports retain the exact rational error alongside them.

The caller must establish: LTR, no wrap, zero margins/padding/border/gaps/insets/scrollbar gutters, no auto margins, no intrinsic size dependence or aspect ratio, definite nonstretch start-aligned cross sizes, no constraints or animation, zero component/artboard origins, identity own transforms, pure-translation ancestry with a supplied error bound, and target preservation during final child layout. The group must contain every actual native participant, in the logical order used by compiler lowering. The modeled native flow is reversed, with physical flex-start preserved by the corresponding native alignment mapping. A different justify-content, helper topology, authored transform, or unproved ancestor requires a different descriptor proof/model path.

These preconditions are explicit assertions in the prototype descriptor, not yet facts mechanically derived by the public compiler. Converting this model to production requires deriving them from the lowering plan, rejecting unresolved cases, and checking all ancestors/descendants and the other axis. Point/factor literal-to-binary32 conversion error relative to CSS decimal syntax is outside this API's exact-serialized-input reference. Intrinsic callbacks and the resource cost of deeply nested groups are also outside it.

## Target arithmetic and branch safety

The pinned native flex algorithm sums hypothetical sizes to choose grow/shrink, freezes inflexible or initially clamped items, computes initial/current free space, applies the below-one factor-sum rule, distributes, then clamps and freezes again (`flexbox.rs:1191–1380`). The prototype requires each initial basis inside its point bounds, so no extra initial active set is needed; both-zero-factor siblings are fixed. It conservatively rejects every possibly active final point/zero clamp. In particular, equal-basic near parent 40 is unresolved because the two rounded targets may clamp asymmetrically and trigger another pass.

With no extra freezes and zero gaps, initial and remaining free space are the same expression. The below-one rule equals multiplication by `min(sum_factors,1)`: for positive free space the native minimum selects that product, and for negative free space the native maximum selects it. Monotone binary32 rounding preserves the relevant order because the unscaled free-space value is already representable. The prototype still charges multiplication and factor-sum error when the actual factor is one, which is conservative.

Growth preserves native division-before-multiplication (`flexbox.rs:1318–1323`). Shrink preserves scaled-basis multiplication, sequential scaled sum, division, multiplication, then basis addition (`1325–1337`). The model checks each intermediate's finite bound and every divisor's positive lower bound. It uses standard absolute forward-error propagation with `u=2^-24` and an absolute minimum-subnormal allowance. A separate `2*minimum_normal` target allowance covers `is_normal()` skipping a subnormal free-space update; exact per-item distribution gains are at most one because all factors and bases are nonnegative.

The ideal grow/shrink joins are continuous at the sum of bases. A native branch disagreement can only occur within `parent_error + used_sum_error` of that threshold. Both ideal per-item gains lie in `[0,1]`; the model therefore adds twice that distance as a conservative branch-join envelope. The native exactly-sized early return is also covered by this envelope. This is an analytical branch bound over the entire interval, not a threshold sample.

A cheap gamma-based sum-uncertainty filter can reject a large group before exact-rational propagation. Its budget depends on participant count and parent extent, not a fixed item/factor limit. It may reject groups that a tighter model could prove safe. Passing that preliminary check is never sufficient: target/divisor/finite/freeze and final-position checks must also pass.

## Final target preservation and placement

For the reviewed fixtures, a/b have definite point cross sizes, no aspect ratio/insets, and no measurement-dependent dimension after main targets are supplied. Their ordinary children may overflow but do not determine these dimensions. `determine_hypothetical_cross_size` takes the definite cross branch (`flexbox.rs:1399–1435`); `determine_used_cross_size` does not alter main targets (`1614–1663`). Final placement calls child layout with both target dimensions known and `ContentSize` (`1936–1946`). Known dimensions take precedence (`210–211`); the child's own main dimension adds zero inset (`288–291`); its cross dimension is clamped again against the same point bounds (`1885–1890`). That clamp is idempotent. Thus the final returned dimensions are the exact native target values under this condition. The earlier `wrapped-slot-size-invariant.md` records the corresponding known-dimension argument; this model uses no wrapped behavior.

The previous r1 position formula was incomplete for reverse CSS. The actual native sequence is now represented:

1. `distribute_remaining_free_space` sums final outer targets in file order and subtracts from the inner container size (`1679–1683`). Zero margins mean outer targets are bit-identical to targets.
2. The frozen compiler emits native reversed flow for all four CSS directions. Ordinary CSS reverses file order and chooses native FlexEnd; reverse CSS retains logical file order and chooses native FlexStart (`public-spacing-checkpoint-r1/source/src/compiler.rs:21–24,471`). Native alignment mapping is in `layout_component_style.rs:266–336`. Thus ordinary CSS's first traversal offset is zero; reverse CSS's is the computed free space, even during overflow (`common/alignment.rs:67–84`). Other offsets are zero (`100–114`). No auto-margin or distributed-alignment branch is entered.
3. With LTR and zero insets, `calculate_layout_line` starts main offset at zero and traverses the reversed file list (`2050–2091`). `calculate_flex_item` publishes `total + item_offset + 0 + 0`, then updates `total += item_offset + 0 + returned_size` (`1967–1971,2016–2019`). The model preserves these parentheses and the file/traversal orders, rather than replacing them algebraically with parent-minus-prefix.
4. Cross origins are exact zero for the fixed start-aligned, nonwrapping fixture path (`1790–1830,2108–2113`). Fixed cross sizes are exact small integers. The arbitrary descriptor API requires separate cross-axis/ancestor proofs instead of inferring them from its main bound.
5. Rounding is disabled (`layout_component.rs:2072–2073`). Taffy results are copied into `Layout` (`2289–2300`), whose constructor stores left/top/width/height directly (`42–57`), and nonanimated publication copies that value (`2396–2405`). There is no bounds-extent subtraction in the probe width/height path.
6. Zero origins and identity own transforms make `layout_translation` just the published position (`901–923`). `compose_world_transform` computes `parent_world * translation * identity` (`989–1013`). Under a pure translation, `Mat2D::multiply` reduces its translation component to one parent-plus-child addition; multiplication by 0/1 and the second identity product are exact (`math/mat2d.rs:255–264`). The model charges this one addition. For the audited fixture parent at world zero it is exact. The origin and identity defaults are bound from generated `artboard_base.rs`, `node_base.rs`, and `transform_component_base.rs`.
7. The baseline probe reads the stored layout width/height and world matrix directly (`baseline-probe.rs:50–68`). Those are precisely the quantities modeled here. Raster path tessellation and screenshot box-edge subtraction are separate numerical paths and are not proved by this account.

The existing factor adapter modifies only Fill fractions and explicit point bases. Native Fill sets both grow and shrink to the fraction (`layout_component.rs:3353–3356`). The runner supplies those actual linked factors to the model, not an independently authored CSS shrink value. In the zero-basis profile the shrink difference is immaterial to scaled-basis arithmetic; that is a separate semantic fact, not an assumed independent native shrink capability.

## Reproduction and scope

Run `python3 tools/html-to-riv/output/flex-numeric-admission-r2/run.py`. `results.json` contains every case and exact bound or diagnostic; `native-observation-checks.json` contains retained-frame comparisons; `observation-sources.json` binds each prior geometry/map file. `receipt.json` binds the scripts/results/review and all source files used by this audit. Immutable source bytes are verified against `6c7ac16617835b5f581784ff08a9e779bb52faf3`. The compiler mapping uses the frozen spacing checkpoint source rather than current actively edited public source.

No runtime/public source was edited, no new native/browser run occurred, and no visual or pixel qualification is added. The remaining work is production descriptor derivation, a practical bounded implementation of the exact/outward arithmetic, CSS input-conversion accounting, and the sixteen unresolved freeze cases. The final-placement operation account is now explicit for the stated structural contract; it should not be generalized to helpers/transforms or intrinsic layouts by adding an arbitrary rounding allowance.
