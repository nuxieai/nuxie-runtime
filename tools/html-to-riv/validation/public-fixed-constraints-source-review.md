# Fixed layout plus sizing constraints: source audit

The minimum sound extension is a closed evaluator over a certified fixed base and the independently bound sizing prefix. Initial geometry seeds alone are insufficient: visible LayoutComponent world matrices change under constraints, and helper children inherit those changed worlds. Keep unsupported objects/fields unresolved rather than evaluating only reachable requested outputs.

## Layout anchors and bounds

Immutable `layout_component.rs:885–899` defines a LayoutComponent anchor as origin fractions times stored layout width/height, enabled only when ComponentOrigin is attached (artboard always has zero local anchor). `local_bounds()` at 1138 uses `(0,0,width,height)`; `constraint_bounds()` returns those local bounds, not layout-left/top or world bounds. The layout translation and authored transform are separate from those extents.

A new ComponentOrigin does not initially translate an identity-linear LayoutComponent: `build_own_transform_with` at 944–979 runs its pivot sandwich only for nonidentity rotation/scale. However, it changes every subsequent constraint landing. Collect and validate origin ownership before evaluation regardless of its file position. Require at most one origin per admitted visible owner, finite admitted fractions, and none on slots or arbitrary helper nodes unless explicitly modeled. Do not replace native bounds width with `world_end-world_start`; the latter may suffer cancellation and is a different graph operation.

## Constraint semantics that cannot be simplified away

- **TransformConstraint** (`constraints/transform_constraint.rs:20–85`) forms local target translation as `bounds.left + bounds.width * originX` and similarly Y, then multiplies target world by that local matrix. Local source space applies inverse *target-parent* world; local destination applies *owner-parent* world. It then decomposes both old and target matrices, interpolates components and recomposes, even at strength one. Finally it lands the owner anchor.
- The decomposition at `math/mat2d.rs:203–240` uses atan2, sqrt, determinant division and compose rotation. Identity-linear inputs can gain negative zero in off-diagonal entries through sin/negation. A narrow translation-only evaluator can model this exact special case, but cannot silently replace the whole result with the target matrix. Subsequent multiplication/inversion/FMA can expose the sign. Retain full six matrix bits and reject any nonidentity-magnitude linear result outside the admitted special case.
- **TranslationConstraint** (`constraints/translation_constraint.rs`) reads old translation first, then performs source conversion, copy-factor and optional offset handling, destination conversion, optional local clamp conversion, max then min comparisons, inverse clamp conversion, interpolation and anchor landing. Disabled copy axes preserve old world translation in world destination space but use zero before local destination conversion. Max/min are conditional comparisons; replacing them with generic float min/max can change signed-zero behavior. At strength one, native still evaluates old*0 + target*1. Finite old state remains required.
- `Constraint::land_anchor` at `constraints/constraint.rs:201–215` returns immediately only when both anchor components compare equal to zero. Otherwise it subtracts `(world[0]*anchor.x + world[2]*anchor.y)*strength` and its Y counterpart. These are ordinary multiply/add expressions, unlike Mat2D's explicit fused point operations. Even an inactive axis passes through its own subtraction when the other anchor component is nonzero.
- **DistanceConstraint** computes transformed owner anchor using ordinary products/additions, then adds it to the owner world translation. It subtracts target *world translation*, computes Vec2D length, applies mode-specific strict comparisons, and returns if distance is below 0.001. Normalization multiplies the delta by desired/current distance; lerp follows, then transformed anchor is subtracted. Do not conflate this early-return path with a unit-sign function or use TransformConstraint target-origin semantics. Preserve the immutable Vec2D length/lerp operation order including its fused operations.

## Dependency and ownership boundary

`TargetedConstraint::build_dependencies` registers the target as a dependency of the constraint owner. Parent transforms are also dependencies; `TransformComponent::apply_constraints` at 188 applies the owner's stored constraints sequentially. Record order is not a global evaluation schedule. A recursive evaluator must visit a parent's final world and every target's final world before composing/evaluating the owner, then apply that owner's constraints in the actual attached order. Reject self/ancestor-target cycles and unknown dependency relationships instead of guessing dirty-cycle behavior.

A constrained visible parent's helper child must compose from the final constrained parent world. Conversely, independently measured slots must retain original layout seeds: visible constraints do not rewrite layout dimensions or trigger repacking. Never overwrite a layout owner's local seed with its final world matrix and then apply parent multiplication a second time.

## Minimum whitelist and decisive checks

Admit only the actual frozen Backboard/Artboard/layout/style/fill/color base accepted by fixed_geometry and existing source/structure binders, followed by the exact independently read sizing grammar: Node, TransformConstraint, TranslationConstraint, DistanceConstraint, and owned ComponentOrigin. Bind base identity, normalized source identity, sizing prefix end and complete record coverage. Extra unknown, dangling or unowned objects must fail even if requested outputs do not reach them. No animation, opacity/collapse changes, rotation/scale, arbitrary targets, unmodeled source/destination/clamp spaces, or runtime inputs should enter by default.

Start with strength-one identity-linear world copies and the exact existing scalar gate graph; each property/default must be whitelisted by the reader. Then qualify original and clone evaluation against the frozen native runtime for every visible and helper matrix, not only final rounded corners. Include center/end ComponentOrigin, reverse wrapping, negative coordinates, zero/inactive axes, local-source cancellation, `<0.001` distance branches and both signs of zero. Parse native JSON `-0` without losing its sign and assert complete owner sets and fixed vector lengths. Native data remains validation output, never seed input.

No product edits, build, or captures were performed for this audit. These observations specify evaluator requirements, not qualification of an implementation.
