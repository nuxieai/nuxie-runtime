The compiler accepts auto or signed integer z-index, CSS-wide keywords and custom-property substitution. Integer zero creates an atomic context; auto permits positioned descendants to participate in an enclosing context. Static flex-item contexts do not establish positioning containing blocks. Integer contexts require version19 layout-css-stacking-v1 metadata and checked host installation. Equal levels follow compiler object occurrence order, which is emitted in CSS order-modified preorder; consumers must preserve object IDs and ordering when using this policy. Grid, opacity/transform context creation and other excluded language features are not admitted by this increment.

The current runtime planner in `crates/nuxie-runtime/src/mechanical_port/source/artboard/css_paint_plan.rs` supports ordinary and auto-z positioned phases only. `PaintTree.positioned` cannot represent integer levels or context boundaries. Sorting the flat drawable list would let nested descendants escape their context and could lose ancestor clipping.

The intended authoring contract is `z-index: auto` or a signed integer, including CSS-wide values and custom-property substitution. Preserve auto separately from integer zero. Integer range/overflow diagnostics must be explicitly defined alongside the existing order parser. Fractional values, lengths and unsupported expressions need explicit rejection. Existing unsupported context-producing features remain outside this increment; later opacity and transforms must integrate with the same context model.

[CSS 2.2 painting order](https://www.w3.org/TR/CSS22/zindex.html) distinguishes auto descendants from atomic zero contexts, with negative contexts before ordinary content and positive contexts afterward. A context paints its own background before its negative descendants. Descendants of an auto positioned node participate in the enclosing context; descendants of an integer context cannot escape it.

[Flex item painting](https://www.w3.org/TR/css-flexbox-1/#painting) uses order-modified document order and creates a context for integer z-index even on a static flex item. This does not make that static item a positioned containing block. Preserve the distinction in host metadata and layout policy. Equal levels require stable paint order independent of row/column reversal.
