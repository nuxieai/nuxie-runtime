# Compiler-private wrapping paint lowering

`src/wrapping_paint.rs` moves the optimized combined experiment's paint composition into a private compiler module. It is not connected to public CSS admission. The caller supplies logical packing-order slot handles and explicit ordered paint lists containing geometry, Fill and SolidColor IDs. No source-map, selector or CSS logic is added to this primitive, and no Fill/color offset is assumed.

All handles and ownership are checked before mutating original colors: slots are distinct LayoutComponents; paint geometry belongs strictly below its own slot without traversing another plan slot; each Fill is uniquely owned by its geometry; each SolidColor is uniquely owned by its Fill. Parent walks are bounded to terminate on invalid cycles. Invalid fractions, duplicate handles, mismatched owners and dangling references diagnose. The complete record expansion and ordinary object-ID capacity are checked before mutation. Runtime coordinate/mask bounds, reliable line separation, independent slots and semantic packing/paint order remain explicit caller proof obligations; the module does not pretend to infer them from a record graph.

Original Fill and SolidColor records are cloned for every replica, preserving authored properties while remapping parent IDs. Original geometry/source IDs remain in place; only the explicit original color values become transparent. `wire::Value` and `wire::Record` derive Clone, and Record exposes a read-only schema-name getter for validated ownership queries. Existing no-wrap output is unaffected by the private module declaration.

For N items with per-item paint counts Pj, define R=sum((j+1)*Pj), S=sum(j*Pj), M=N(N−1)/2. When any paint exists, exact added records are **8N−5+7M+3R+2(R−1)+2S**. All-zero lists emit zero records, and unpainted items remain in the packing-order plan because they affect line boundaries. Checked arithmetic rejects overflow. Four unit tests verify nonuniform/zero lists and counts through 32 items, preserved Fill properties and paint order, pre-mutation rejection of invalid ownership/duplicates/cycles, and fraction/empty-plan behavior. The library checkpoint passed all 12 tests. The first test build's Rust borrow-check failure and corrected second build log are preserved.

The ignored harness in `output/wrapping-paint-module-r1` imports the actual private module and actual wire source. It reads the frozen combined experiment's sized files, finds explicit Fill/color ownership through schema-name properties, supplies the B/A/C slot and parent/descendant plans, and emits the final file. **All 48 resulting RIV files exactly match the completed combined-optimized experiment; a second invocation reproduces all 48 outputs identically.** The unit tests cover varying paint-list sizes beyond the two-paints-per-item corpus. Existing pixel/geometry evidence applies to those exact 48 file bytes; no new raster or broader arbitrary-tree qualification is asserted by this module test.

The receipt binds private source hashes, harness/build commands, logs and file identities. Parent-task changes to CSS routing or other compiler features require their own validation. No runtime, renderer, schema dependency or shared build configuration was modified, and this subtask made no commit.
