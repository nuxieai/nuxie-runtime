# Public preferred-axis image constraints: partial support

The compiler now admits an image with one percentage preferred dimension, an automatic opposite dimension and homogeneous point or percentage min/max bounds on the preferred axis. It emits ordinary responsive layout properties and the original encoded image asset. Runtime, renderer, schema, shared dependencies and host behavior are unchanged; no browser geometry, fixed viewport result or resize recompilation is required.

Point bounds keep the authored preferred percentage and preferred-axis bounds. The compiler explicitly transfers source-derived ratio limits to the automatic axis, normalizing minimum-wins conflicts before deriving the opposite maximum. This repairs the initial direct native candidate, which clamped the preferred dimension but left the automatic dimension too small. Homogeneous percentage bounds share the preferred dimension's original containing basis, so the compiler clamps their source coefficients and emits a resulting percentage. For example, `width:50%; min-width:75%` becomes an ordinary 75% width, still responsive. Authored computed style remains unchanged; selected scalar provenance and actual native floating-point operations are retained in the lowered plan.

## Admitted and unresolved contexts

The profile has exactly one percentage preferred axis, an automatic opposite axis, zero image padding, default opposite-axis bounds and homogeneous preferred-axis bounds. It covers maximum-only, minimum-only, ordered and conflicting bounds. The default zero minimum is compatible with either bound unit. Existing image asset, margin, alignment, fit and numerical restrictions remain in force. Native evidence covers flex-start alignment, both row and column parents, and definite parents with and without point padding. The padded boundary matrix crosses lower, interior and upper branches for point bounds while the same file resizes.

Mixed point/percentage preferred bounds, simultaneous opposite-axis bounds, automatic minima, image padding, genuine automatic cross stretch and nonlegacy flex sizing remain diagnosed or outside qualification. Two definite or two automatic preferred dimensions use other established paths or diagnostics. This checkpoint does not broaden all surrounding flex/container semantics merely because the selected image recipes work.

Numerical validation checks the actual emitted preferred and opposite bounds, the ratio-derived intermediate and final image-fit arithmetic. Transferred point values retain both the ideal ratio from encoded intrinsic dimensions and the actual binary32 aspect-ratio multiplication/division. Missing provenance, tiny nonzero unsupported padding and nonfinite derived bounds remain rejected. Passing this finite numerical and native matrix does not establish arbitrary CSS equivalence.
