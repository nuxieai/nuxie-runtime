# Lazy variable-cycle resolution

The temporary fallback-cycle rejection is removed. Custom-property resolution visits a fallback only when the primary reference is invalid or missing. A repeated active property invalidates the actual cycle participants; their own fallbacks cannot rescue them. Outside dependents can recover after the cycle unwinds. Resolution continues through sibling expressions after failure, so a later reference can still reveal a cycle. Token, inheritance and resource boundaries remain unchanged.

This follows the [current CSS Variables draft](https://drafts.csswg.org/css-variables-1/#substitute-a-var) and [CSS Values substitution guards](https://drafts.csswg.org/css-values-5/#substitute-arbitrary-substitution-function). Our initial implementation used the older published dependency-graph formulation. The pinned Chromium tag has direct regression tests for [an unused self-cycle fallback](https://chromium.googlesource.com/chromium/src/+/refs/tags/153.0.8010.12/third_party/blink/renderer/core/css/resolver/style_cascade_test.cc#1044) and [an outside dependent recovering from a cycle](https://chromium.googlesource.com/chromium/src/+/refs/tags/153.0.8010.12/third_party/blink/renderer/core/css/resolver/style_cascade_test.cc#1097). Its [resolver implementation](https://chromium.googlesource.com/chromium/src/+/refs/tags/153.0.8010.12/third_party/blink/renderer/core/css/resolver/style_cascade.cc#2090) skips unused fallbacks and continues sibling substitutions after failures.

The graphs include unused/traversed self and mutual references, direct cycles with own fallbacks, outside recovery, multiple cycle components and empty primary values. These observations are finite evidence, not a proof of arbitrary graph equivalence.
