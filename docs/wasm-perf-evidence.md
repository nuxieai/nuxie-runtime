Each side uses fresh total and phase-pass instances, primes retained topology before timing, and reports multiple independent runs. Browser timings use monotonic `performance.now()` around the same production advance and draw calls as the native facade. Scripted, input-driven, and image-decoding fixtures are unsupported and fail closed; very small phase values may show browser-clock quantization.

Before staging any coordinator, the launcher required a clean tracked checkout and captured Git commit `7adbf3c406a66ad4d2ecdab6d90d7c1f5f9c72ec` and tree `9b8499dc3d28891b8ce0c68d4124c70c34cfc3a2`. It extracted the bootstrap Python directly from that commit object; that exact bootstrap then read shell, Python, Node, and driver bytes from the captured commit's Git blobs, recorded the same commit/tree in the bundle manifest, and reverified the source identity before the launcher replaced itself with the sealed shell. The sealed shell rejects an inherited bundle before reading runtime environment variables unless its directory has an exact 64-character lowercase SHA-256 name, the manifest digest matches that name, the manifest records the current clean source commit/tree, and the directory contains exactly the four hash-verified coordinator members. During validation, the shell captures the manifest-authenticated Python member's byte count and SHA-256. Immediately after opening that member, it rehashes the exact descriptor and compares both values against the captured identity before it reads runtime environment variables. The shell then retains that same descriptor across audit, preparation, sealing, and finalization; each phase rewinds, reads, and executes it. Consequently, replacing the Python path either between validation and open or after sealing cannot change trusted finalizer code undetected. The Node process independently reported its executed identity for final verification. The browser read and verified the exact HTML and driver bytes from the seal, served and executed them only from SHA-addressed intercepted URLs, fetched the exact sealed wasm-bindgen JavaScript and Wasm buffers, and reported all four executed browser artifact identities for verification. Each of the five fixture files expanded to all three authored corpus samples (`0s`, `0.5s`, and `1s`); each browser and native run recorded and verified the same fixture ID, sample index, and sample seconds before comparison. All 15 targets recorded five independent measured runs per side after one discarded browser warmup, and each measured run executed exactly 100 segments. Native measurement copied the verified runner bytes to a private content-addressed executable and invoked only that sealed copy. The Wasm runner enabled deterministic runtime mode before importing each fixture, matching the native runner's deterministic setup. Finalization reverified the independent seal, clean source identities, coordinator/runtime artifacts, fixture bytes, complete 15-target measurement contract, and executed identities after measurement. The Browser WebGPU pull-request job invokes `make wasm-perf-test`, which runs the 40 Python contract tests and eight Node contract tests that protect these invariants.

Reproduce with `make wasm-perf` from clean source and rive-runtime checkouts. The command writes the complete `nuxie-wasm-perf-v1` machine report, including all per-run timings, fixture/sample target identity, source trees, coordinator/runtime artifact and fixture hashes, accounted time, bookkeeping, and segment counts, to `target/wasm-perf.json` and the generated table to `target/wasm-perf.md`.
