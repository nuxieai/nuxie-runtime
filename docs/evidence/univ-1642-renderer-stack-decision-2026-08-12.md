# UNIV-1642 renderer stack decision

Status: accepted on 2026-08-12. This decision proves a direction and its safety
gates; it does not enable the native-shader shipping path.

## Decision

The Apple device SDK will use wgpu's Metal passthrough path with committed,
offline-generated MSL. Editor, browser, and ordinary development builds will
retain the current WGSL/Naga path. We will not start with a direct `wgpu-hal`
Metal renderer.

This is a build-tier split:

| Tier | Shader input | Compiler ownership |
|---|---|---|
| Apple device SDK | committed MSL plus an explicit binding/reflection contract | repository release tooling and the authored-asset pipeline |
| Editor and development | WGSL | runtime Naga, for authoring and diagnostics |
| Browser | WGSL through wgpu | unchanged |

The future Apple feature must be opt-in from `apple-runtime`. A missing,
untrusted, corrupt, or incompatible native artifact is a hard error; the
shipping feature must not silently fall back to runtime WGSL compilation.

For this decision, “Naga-free device SDK” describes the final linked Apple
artifact, not the Cargo package graph. The pinned wgpu core/HAL APIs retain
Naga types, and the Metal HAL currently enables Naga's MSL output support even
when passthrough is used. The shipping gate is therefore absence of reachable
WGSL parsing, validation, MSL generation, diagnostics, and associated data in
every representative final Mach-O. If fat LTO and dead stripping do not remove
that code, a narrowly audited wgpu feature split is required before the gate can
pass. Merely observing `naga` in `cargo tree`, or merely enabling passthrough,
neither proves nor disproves the linked-artifact result.

## Why this direction is viable

The pinned wgpu 30 stack exposes
`Device::create_shader_module_passthrough`, accepts MSL source, and advertises
the path through `Features::PASSTHROUGH_SHADERS` on Metal. The repository's
`renderer-apple-passthrough-probe` creates an MSL module and a render pipeline
with an explicit layout on a real macOS Metal device. It clears the instance
flags that otherwise compile wgpu's internal indirect-validation and timestamp-
normalization WGSL during device creation. This proves that wgpu can carry
native shaders without a direct-HAL rewrite.

The probe is deliberately not a shipping proof. The API is unsafe because wgpu
does not validate passthrough source. Invalid source, entry points, bindings, or
vertex mappings may crash the driver or render incorrect output.

## Offline compilation ownership

Built-in shaders will be generated by repository-controlled tooling pinned to
the exact Naga/wgpu revisions used by the runtime. A Make target will regenerate
the complete catalog and `renderer-shaders-check` will reject drift. Generated
MSL and its manifest will be committed so review and release builds do not run
a customer-build `build.rs` compiler.

The first artifact format is MSL source. A metallib may be evaluated later as a
pipeline-startup optimization, but it adds Xcode and SDK versions to artifact
provenance and is not necessary to remove runtime WGSL compilation.

Authored shaders have different ownership. The asset pipeline is authoritative,
and Apple must consume RSTB v4 Metal target 2 together with BindingMap target
10. WebGPU targets 0 and 16 remain the editor/browser representation. Native
RSTB selection cannot ship until it has a fail-closed trust and reflection
contract equivalent to the validation performed from WGSL today.

Parsing RSTB `SignedContent` is not signature verification. The authored-native
slice must define and enforce a cryptographic trust policy, or an equivalently
fail-closed provenance boundary, before target 2 reaches unsafe passthrough.

## Complete permutation contract

A syntactic WGSL-to-MSL translation is insufficient. wgpu's Metal backend maps
resources and vertex inputs using pipeline state, so each generated built-in
artifact must be keyed by all inputs that can alter its ABI or code:

- shader source digest, stage, and entry point;
- ordered bind-group layouts and the resulting Metal resource-slot map;
- vertex-buffer layouts and generated vertex-attribute mappings;
- specialization/constants and renderer mode or shader variant;
- sample count and target/depth formats when they affect generation;
- device MSL version and zero-initialized-workgroup-memory policy;
- primitive topology class and generated point-size behavior;
- binding-array lengths, the full per-stage resource map, and vertex mappings;
- every runtime-check flag used for the corresponding WGSL module; and
- Metal compile options, including the repository's conditional
  `preserveInvariance` parity behavior.

All direct built-in shader-module creation sites must eventually route through
one catalog seam. Its manifest must enumerate every runtime-reachable key and
reject duplicate, missing, stale, or unreferenced artifacts. RSTB BindingMap
data is not by itself a complete replacement for current WGSL reflection: the
native authored path must also validate entry-point I/O and minimum uniform
buffer sizes before it can use the unsafe passthrough API. It must additionally
prove target-10 slots match wgpu-hal's Metal allocation exactly and supply
missing compute workgroup reflection.

MSL source is an artifact-format choice, not a claim that moving source alone
preserves output. wgpu's normal Metal path selects `MTLLanguageVersion` and
conditionally enables `preserveInvariance`; its current passthrough path uses
default `MTLCompileOptions`. The generator/loader slice must either carry the
same options into passthrough compilation or prove equivalent behavior across
the supported device matrix.

## Shipping gates

The Apple feature may be enabled only after all of these are true:

1. Layout-aware built-in generation covers every reachable pipeline key and
   `renderer-shaders-check` proves catalog freshness. Its tests cover wgpu's
   MSL-version, workgroup initialization, topology, binding-array, resource,
   vertex-map, runtime-check, and Metal compile-option inputs.
   A source ratchet proves the renderer uses no indirect draw/dispatch calls,
   `VALIDATION_INDIRECT_CALL` and `AUTOMATIC_TIMESTAMP_NORMALIZATION` remain
   disabled, and the pinned wgpu configuration builds without its `wgsl`
   feature so internal wgpu shaders cannot reintroduce runtime compilation.
2. Authored RSTB target 2/10 selection rejects absent, malformed, untrusted, or
   reflection-incompatible assets without a WGSL fallback.
3. Current renderer goldens and fuzz replay pass on both WGSL and native paths.
4. Multi-bind-group, vertex-mapping, authored-shader, and malformed-artifact
   fixtures exercise the binding and trust boundaries.
5. A committed Apple support matrix enumerates deployment minimums, CPU
   architectures, Metal GPU families or representative hardware, and simulator
   versus physical-device rows. Real-device iOS and macOS goldens record
   reproducible provenance for every required row.
6. The final five-slice Apple artifact is measured. Dependency and linked-symbol
   attribution, link-map/symbol inspection, representative string/data checks,
   and the size report prove that Naga compiler and diagnostic implementation
   is not linked. The dependency report records the remaining wgpu type-level
   relationship but is not treated as an absence proof.

Only after the feature flip and measurement should UNIV-1643 reconsider the
remaining wgpu-core/HAL cost. The estimated 550–750 KB saving remains a target,
not evidence produced by this decision.

## Deferred implementation slices

UNIV-1642 resolves the architecture choice. Production work is split into
three ordered follow-ups under UNIV-1641:

1. UNIV-2072: a layout-aware built-in artifact catalog and pinned MSL generator;
2. UNIV-2073: an authored RSTB target-2/10 path with fail-closed reflection and
   trust; and
3. UNIV-2074: a committed device matrix, dual-path real-device parity, the
   Apple feature flip, and final Mach-O size and Naga-absence evidence.

The third slice depends on the first two and blocks the UNIV-1643 direct-HAL
reassessment. No dormant shipping feature, generated production shader, RSTB
decoder change, or Apple feature wiring is part of this decision PR.
