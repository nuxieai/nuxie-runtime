Before staging any coordinator, the launcher required a clean tracked checkout and captured Git commit `fc2b02f012d54430ac50fdca7d921f09e677d635` and tree `917a39cc4758f87db0a792880f982214dbf7cede`. It extracted the bootstrap Python directly from that commit object; that exact bootstrap then read shell, Python, Node, and driver bytes from the captured commit's Git blobs, recorded the same commit/tree in the bundle manifest, and reverified the source identity before the launcher replaced itself with the sealed shell. The sealed shell rejects an inherited bundle before reading runtime environment variables unless its directory has an exact 64-character lowercase SHA-256 name, the manifest digest matches that name, the manifest records the current clean source commit/tree, and the directory contains exactly the four hash-verified coordinator members. During validation, the shell captures the manifest-authenticated byte count and SHA-256 for the Python, Node, and driver members. Immediately after opening all three members, it rehashes each exact descriptor and compares both values against the captured identities before it reads runtime environment variables. The shell retains the Python descriptor across audit, preparation, sealing, and finalization; each phase rewinds, reads, and executes it. It also executes Node from its retained descriptor, and Node loads the driver from its retained descriptor while reporting the manifest-authenticated Node identity for final verification. Consequently, replacing any coordinator path after its descriptor is opened cannot change the trusted coordinator code that executes. The browser read and verified the exact HTML and driver bytes from the seal, served and executed them only from SHA-addressed intercepted URLs, fetched the exact sealed wasm-bindgen JavaScript and Wasm buffers, and reported all four executed browser artifact identities for verification. Each of the five fixture files expanded to all three authored corpus samples (`0s`, `0.5s`, and `1s`); each browser and native run recorded and verified the same fixture ID, sample index, and sample seconds before comparison. All 15 targets recorded five independent measured runs per side after one discarded browser warmup, and each measured run executed exactly 100 segments. Native measurement copied the verified runner bytes to a private content-addressed executable and invoked only that sealed copy. The Wasm runner enabled deterministic runtime mode before importing each fixture, matching the native runner's deterministic setup. Finalization reverified the independent seal, clean source identities, coordinator/runtime artifacts, fixture bytes, complete 15-target measurement contract, and executed identities after measurement. The Browser WebGPU pull-request job invokes `make wasm-perf-test`, which runs the 40 Python contract tests and eight Node contract tests that protect these invariants.

Reproduce with `make wasm-perf` from clean source and rive-runtime checkouts. The command writes the complete `nuxie-wasm-perf-v1` machine report, including all per-run timings, fixture/sample target identity, source trees, coordinator/runtime artifact and fixture hashes, accounted time, bookkeeping, and segment counts, to `target/wasm-perf.json` and the generated table to `target/wasm-perf.md`.
