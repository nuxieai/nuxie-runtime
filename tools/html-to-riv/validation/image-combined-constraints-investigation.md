# Combined automatic-axis image constraints

Private ordinary-file experiment only. No public source or runtime changes. The single image owner retains one authored percentage preferred axis, an automatic opposite axis, and intrinsic aspect ratio. Both ordinary minimum components are explicit, and the maximum in the authored preferred axis is copied from that preferred percentage. This suppresses native bound-vector completion on either bound vector while allowing independent automatic-axis min/max arbitration.

The frozen generator and matrix are `image-combined-constraints-candidate.py` and `image-combined-constraints-cases.json`. The24 recipes cover six combined-bound families, both preferred axes, and both parent flex directions: ordered point bounds; conflicting point bounds; point minimum with percentage maximum; percentage minimum with point maximum; ordered percentage bounds; conflicting percentage bounds. The last four families use20px parent padding, so both opposite-axis percentage bases must remain the original parent content dimensions. Every image has zero padding and flex-start alignment. Original encoded opaque96×64 asset bytes are retained. The old public percentage-padding build supplies accepted unconstrained seeds and rejects every authored constrained request. No browser geometry is consumed during emission.

`output/image-combined-constraints-candidate-r1/combined-receipt.json` records192 fresh frames from24 ordinary files, each original and clone resized without recompilation through the existing four-step sequence. All192 geometry and image-presence checks pass.182pixel checks pass;10failures remain at unchanged tolerances. The failures occur in height-preferred percentage-minimum/point-maximum row cases (2frames), height-preferred conflicting-percentage row cases (2frames), and width-preferred ordered-percentage column cases (6frames). Exact failure names and categories are retained in `image-combined-constraints-receipt.json`.

This demonstrates a viable native candidate for simultaneous automatic-axis bounds, including percentage minima and minimum-wins conflicts. It does not establish public API admission or full pixel equivalence. Direct visual review is complete: all 24 original-resolution sheets and 72 representative Chrome/native pairs were inspected, with 120 exact visual transfers covering all 192 frames. The completed review is bound by `image-combined-constraints-receipt.json`. The image pattern, row/column tail direction and padded origins agree in the finite matrix; all 10 local tail pixel failures remain. Viewport-clipped content in wide cases is visible in both renderers, without a claim about offscreen pixels. Preferred-axis constraints, image padding, stretch, automatic flex minima and nonlegacy flex sizing remain outside this experiment.

Public integration would need to carry both authored automatic-axis bounds and their original percentage provenance through planning, emit both minima with their actual units (not force every minimum to Point), and apply bounds against the original parent axis in numeric validation. Preserve checks on the pre-clamp ratio intermediate and the post-clamp fit arithmetic. Do not normalize a point/percentage min/max conflict at compile time because its ordering can change on resize.
