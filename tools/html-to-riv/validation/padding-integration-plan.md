# Private padding module and integration sequence

`src/padding.rs` now provides a compiler-private computed model and ordinary LayoutComponentStyle emission. Seven source-mounted tests pass; the harness and hashes are retained in `output/padding-module-tests-r2/` and `padding-module-receipt.json`. No compiler.rs or runtime edits were made for this module task. Declaring/calling the module remains an integration change owned by the main compiler work.

## Computed seam

Add `#[path = "padding.rs"] mod padding` next to margins, and `padding: Padding` with zero default to Style. The model stores physical left/top/right/bottom as `Inset::Pixels(f32)` or `Inset::Percent(f32)`; Auto cannot occur. `Padding::apply(name,text,parent,font_size,source)` tokenizes shorthand/longhands with cssparser, including comments, exponent numeric syntax, case-insensitive units/keywords, nonnegative px/em/rem/percent and numeric zero spellings. CSS-wide keywords apply atomically to the complete declaration. Inherit copies computed px or percentage descriptors; unset/initial reset to zero. Percentages retain the authored f32 number lexeme, avoiding percentage→fraction→percentage rounding (0.027% regression). Font-relative values use existing computed-length limits and root font size.

Call apply only after `computed()` has substituted variables and completed its font-size pass. The module deliberately does not expand var(), calc(), custom properties or cascade. Add recognized declarations to strict loser validation as well as winning declaration handling; recognition alone must not admit nonzero padding publicly. Private PaddingCandidate may route native evidence while Public and existing FlexCandidate remain guarded. Zero declarations/inheritance must preserve previous bytes and all existing strict-loser behavior.

`Padding::emit(&mut Record)` writes nonzero value/unit pairs on a fresh LayoutComponentStyle; it must be called once for that box after its layout_box emits the style. It adds no objects and omits both fields for every zero side, including zero percent. Do not use this append-style emitter to clear fields on a previously padded record. `sides()`, `is_zero()` and `has_percentage()` expose descriptors needed by admission/numeric/baseline logic without resolving percentages against an input viewport.

## Numeric and containing-block seam

`numeric::Bounds::child` currently models border-box width/height as the next containing size. Padding requires distinguishing outer-box bounds from descendant content-box bounds. Resolve every percentage side against the parent's **content width**, regardless of axis. Model the actual immutable padding path (`value/100` then LengthPercentage resolution), not the distinct rive_yoga_percent dimension arithmetic. Include finite side sums and padding floors: outer used size is floored by padding+border even when it exceeds a maximum. A finite max alone cannot cap an overflowing padding sum.

For a content upper bound, subtract a proven padding **lower** bound from an outer upper bound; subtracting padding upper from outer upper is not conservative. Percentage lower bounds may be zero over the allowed resize domain. A tighter interval/affine relationship may retain percentage dependence, but unknown is preferable to a false certificate. Keep lower overflow witnesses independent and account for floors in them too. Intrinsic unknowns and flexible used sizes remain unknown unless separately proven. An initial private candidate may explicitly mark padded outer/content bounds Unknown, stopping percentage inference; this is a scope limitation, not a complete public numeric proof. Public exposure still requires a justified numeric contract over all admitted resize inputs.

## Layout and baseline guards

Padding belongs to the authored box, whose background paints its outer dimensions. Synthetic alignment wrappers and flex spacers receive zero padding. However, padding moved inside an alignment wrapper can change both the intrinsic outer main extent and percentage containing width. In a row, a percentage-padded authored child may incorrectly resolve against wrapper width instead of the original container width. Initially diagnose nonzero padding on a box needing a perpendicular alignment wrapper; do not assume fixed px padding settles wrapper floors/bounds either. Later tests must cover bounded main dimensions, percentage padding, safe overflow and source identity before removing that guard.

`baseline::used_height`, `summarize` and `summarize_last` cannot reuse unpadded descendant offsets or intrinsic heights. Empty synthesized baselines depend on final border-box size; inherited first/last descendant metrics need content origin offsets and padding floors. Initially invalidate padded subtree summaries and diagnose baseline-sharing groups that depend on them, including unpadded ancestors with padded descendants. Add proof/metadata rather than only checking the immediate participant's style. This keeps unproved metrics from leaking into an apparently unpadded outer baseline group.

Keep nonzero-padding plus nonlegacy flex, main auto-margin/distribution helpers, wrapping and cross-slot layouts outside initial candidate admission until their joint cases are checked. Content-box stays a separate composition candidate: the native padding experiment preserves32 direct-mapping failures. Do not convert widths/min/max by adding padding without accounting for percentages and intrinsic sizes.

## Required checks before public exposure

1. Run module tests through the actual crate once declared, then add pipeline tests for font-size declaration order, var fallbacks, shorthand/longhand cascade, inheritance across different fonts, strict losing declarations, unsupported functions and zero-byte regression. The isolated harness currently tests parsing/computed descriptors, not that pipeline.
2. Reproduce the20 border-box native fixtures from `output/padding-native-r1/cases.json`; preserve the two fractional leaf pixel failures. Keep four content-box controls as explicit negatives. Compare emitted ordinary field semantics, source maps, original/clone resize, pixels and visual coverage.
3. Add high-exponent side values/sums, padding exceeding declared width/max, nested percentage chains using content width, percent top/bottom under column flow, and intrinsic percentage cycles. Exercise numerical guards at multiple resize sizes; do not certify from samples alone.
4. Add guarded and eventual admitted padded baseline subtrees, alignment wrappers, ordered siblings, flex basis, min/max freezes, auto margins and spacing helpers. A guard must identify the actual failing source/context and preserve already qualified zero-padding behavior.
5. Run native/CLI/WASM parity, established byte/map regression, full visual evidence and documented support/limitations before changing the public whitelist or backlog status. Preserve all99 roadmap items; private staging is not completion of padding or content-box support.
