# Exact fixed geometry seeds for paint folding

Add a small compiler-owned native-layout evaluator for the closed fixed public base shape. Existing domains are prerequisites, not singleton world-coordinate certificates: `wrapping_coordinates.rs:71–97` deliberately takes hulls over unknown line counts/positions even when input sizes are singleton, and `wrapping_position.rs` propagates error bounds rather than a unique native transform. Extracting a bound endpoint would be unsound.

The proposed seed reader consumes actual source-built base records plus their existing source-binding token; it does not import runtime code/dependencies, execute a native probe, or read captured geometry. It returns exact f32 layout fields and identity-linear world matrices indexed by existing owner IDs, without editing the scene or map. The separate fixed-scalar interpreter then evaluates the emitted sizing/position constraints from these initial seeds. Initial visible corners are not final constrained corners.

## Minimum closed certificate

Reuse the structural reader's Artboard → wrapping parent → slot → visible shape and exact source-bound preferred/min/max records. Require fixed units for all effective sizes, no intrinsic/percentage/auto preferred dimensions, zero margins/insets/padding/borders/gaps, zero grow/shrink, auto basis, LTR, known positional alignment, no animations, identity scale/rotation and zero authored translations. Max-auto and explicit min/max remain allowed and bound. The artboard origin is zero and its sole fixed child is top-left aligned. The seed proof owns encoded base identity and every effective source/record binding; arbitrary caller-provided position arrays are not certificates.

Read parent direction, wrap reversal and alignment from actual style fields. The immutable `layout_component_style.rs:274–351` couples positional cross-axis align-items and align-content, so seed slot positions must include both terms. Generated stretch slots are already fixed actual records: use their expanded fields directly after the stretch source certificate binds them. Do not independently reapply stretch.

The fixed root extent/position is independent of artboard width/height: fixed dimensions and zero flex factors keep its used size; top-left alignment produces zero offsets even under overflow. Verify that exact root style premise. The viewport itself remains symbolic and is consumed only by artboard clipping, not replaced by compile dimensions.

## Native operation sequence

Use f32 operations at each step, with finite checks and no f64 reassociation or fused multiply-add. Preserve signed zero or explicitly discharge its irrelevance before canonicalization. References below are in `vendor/taffy-0.12.1-rive-yoga-order/src/compute/flexbox.rs` unless stated otherwise.

1. **Effective dimensions.** Resolve emitted fixed values and clamp preferred against max then min. Known zero insets and borders add no extent. Match the frozen leaf/target-size path rather than reconstructing dimensions from transformed edges. A useful initial domain additionally proves raw LayoutUnit values and every relevant sum below 65536px; broaden only with explicit operation bounds. Source minima must remain distinct from generated-slot minima.
2. **Packing (872–943).** Source-order accumulator starts at +0. For each candidate item, compute `next = fl(sum + fl(hypothetical_main + gap_contribution))`, with gap contribution zero. Start a new line only when next exceeds available main extent and the candidate is not first. Reset the accumulator for the next line. Reverse direction does not reverse source packing.
3. **Line cross extents.** With fixed, nonbaseline children, each line maximum is the maximum used slot cross extent. Record line membership explicitly. For public positional base records do not run native align-content stretch. There is no native pixel rounding: runtime `layout_component.rs:2073` disables Taffy rounding.
4. **Main free space (1677 onward).** Sum outer target main sizes in source line order using sequential f32 additions; `used = fl(0 + sum)` and `free = fl(parent_main - used)`. The first item in physical traversal receives the positional offset; subsequent items receive zero. With native FlexStart that first offset is free for reverse main and zero otherwise. Center uses `free / 2`; FlexEnd swaps the endpoints. The exact helper is `compute/common/alignment.rs:59–133`.
5. **Cross free space (1904).** Sum line cross sizes in source line order, then `free = fl(fl(parent_cross - total_cross) - 0)`. The first physically traversed line receives the content offset using the same helper and reverse-cross flag; subsequent line offsets are zero. Each slot independently receives `item_cross = fl(line_cross - slot_cross)` times the effective item fraction (0, /2, or identity), with wrap reversal applied by the native FlexStart/FlexEnd branches at 1790 onward.
6. **Physical traversal (2039–2148).** In LTR, initialize cross accumulator T=0; visit lines reversed iff wrap-reverse. For each line initialize main accumulator U=0; visit items reversed iff main direction reversed. For each item evaluate `main_location = fl(fl(fl(U + item_main_offset) + 0) + 0)` and `cross_location = fl(fl(fl(fl(T + item_cross_offset) + line_offset) + 0) + 0)`. Update U with `U = fl(U + fl(fl(item_main_offset + 0) + actual_main_size))`. At line end update T with `T = fl(T + fl(line_offset + line_cross_size))`. Preserve this placement/update ordering; do not use a visually equivalent `parent - prefix - size` formula.
7. **Visible child local layout.** Evaluate the one-child fixed slot using its actual default direction/alignment and min/max, not the authored child's ignored flex direction. A default nonwrapping slot has line cross size determined by its fixed container; admitted top-left alignment still gives local origin zero. Explicitly verify that premise in the reader. Its visible extent is its own clamped fixed size, which may differ from slot extent.
8. **World composition.** Native `layout_component.rs:2289–2300` stores returned location and width/height separately in Layout; it does not reconstruct extents by subtraction. `layout_translation()` at 901 subtracts artboard origin (bound zero). `compose_world_transform()` at 989–1013 multiplies `parent_world * translation(layout) * own`. Match immutable matrix operation order when evaluating the seed; with identity linear parts, authored translation zero and finite values this reduces to the corresponding ordered translation additions. ComponentOrigin does not change the initial identity-linear transform (the nonidentity pivot branch is skipped), but it matters when subsequent constraints land anchors.

These steps intentionally retain actual f32 positions. Source CSS LayoutUnit positions can differ slightly, especially centered odd LayoutUnits. The paint optimizer must first preserve the qualified native scene's machine behavior; Chrome fidelity remains a separate comparison.

## Bounded implementation and checks

Implement `fixed_geometry::bind(base, source_binding)` first for positive fixed slot/visible dimensions, zero visible local offsets, and positional fractions 0/0.5/1, both reversals. Return owner size bits, local-origin bits and initial world-matrix bits together with a base-bound private token. Keep ordinary sizing records and source-map IDs untouched. Have the existing domains and closed scalar binding validate the completed composition, then pass only certified seeds into the independent scalar interpreter.

Unit cases: one and multiple lines, unequal extents, reversed traversal, oversized first item, exact-fit/one-unit boundaries, negative cross free space, parent and child min-over-max, differing expanded slot/visible sizes, and cancellation-sensitive fractional offsets. Mutation controls: wrong root alignment/origin, percentage units, animation/scale, nonzero hidden inset, shared or swapped styles, another same-ID source scene, changed visible bounds and changed reversal. Zero extents can be added after their packing/separation implications are explicitly bound.

The first frozen experiment compares the reader's seed bits to actual native base layout for a tiny retained corpus as validation only; native observations never enter constructor inputs. Then compare interpreted final world corners to the unchanged complete sizing graph, before attempting paint suffix folding. Preserve every mismatch and qualify clone/repeated artboard resize. This separates a seed-evaluator bug from a scalar-interpreter bug and makes the cheapest next paint-fold experiment reviewable.
