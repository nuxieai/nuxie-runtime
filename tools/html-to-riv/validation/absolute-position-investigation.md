# Absolute positioning investigation (L18)

Status: investigating, public syntax remains rejected.

The runtime already maps YGPositionType::Absolute to Taffy Position::Absolute
in layout/layout_style_applier.rs. The compiler currently stores a relative_position
boolean and emits positionTypeValue plus physical offsets only for relative nodes.
That state needs an explicit position mode before absolute admission.

A second seam needs testing: LayoutComponent::position_type_changed_from_style
fills left/top from current layout when corresponding change flags are absent.
CSS auto insets must survive installation and clone/resize; this callback must
not silently replace them with frozen coordinates.

Qualification work must cover removal from flex flow, all-auto static position,
nearest positioned containing block through static ancestors, padding-box
percentage bases, opposite insets with auto sizing, min/max constraints, auto
margins, nested positioning, order, clipping, text/images and original/clone resize.
Start with browser reference fixtures and a runtime diagnostic; do not expose a
parent-only approximation as full CSS containing-block semantics. Existing v17
positioned paint policy is a candidate for reuse, subject to pixel evidence.
Fixed/sticky, Grid and editor integration remain outside scope.
