# Immutable renderer audit

**Current decision:** PR #629 is merged and the baseline is restored. Static rasterization, fixed-viewport output, host wrappers and recompilation on resize mentioned below are tradeoff candidates outside the approved responsive-file contract; none is adopted. File-level ordinary-Rive compositions are the only shim strategy currently authorized. See ../TARGET.md.

Audit range: `6c7ac16617835b5f581784ff08a9e779bb52faf3` (required immutable pre-PR baseline) → `20248ee6835a7bb071dbf83a364606f5e58aeef9` (merged implementation). Read-only audit on 2026-09-11; no builds, GPU runs or implementation changes. This document is the only new write for this task. Interrupted uncommitted P07 renderer edits are outside this commit range and remain untouched as archive; they are not release evidence.

The range changes **44 files, 3,157 insertions and 143 deletions** across `nuxie-render-api`, `nuxie-render-stream` and `nuxie-renderer`. These are material execution changes, not just standalone compiler serialization. Earlier successful Chrome comparisons used these modified hosts and cannot qualify the immutable baseline.

All line references in the inventory are **at the audited end commit**, using the first added/changed hunk as an entry point; inspect with `git show 20248ee6835a7bb071dbf83a364606f5e58aeef9:PATH`. ## What can be represented with existing Rive objects?

These are architectural alternatives, **not newly validated implementations**. A compiler may emit more ordinary objects or baked assets; it may not install the PR's custom Factory/Renderer methods, stream operations, runtime policies or shaders under a different module name. Calling a pre-existing host API is also not proof that the same operation is serializable in a `.riv` file.

|---|---|---|

Clip child wrappers with ordinary ClippingShape. | Structurally plausible for a resolved viewport. Exact inner/outer corner math, translucent overlap avoidance and responsive sizing must be requalified on baseline. No need for exact-gradient factory just to draw a solid border. |

## General bug fixes versus compiler-specific execution additions

1. **Ordinary Atomics image edge coverage is a general rendering bug fix.** End-commit `atomic_draw_glsl.rs:235–253` uses inverse-transpose column0 for constant local-x edges and column1 for local-y. Baseline swaps these, causing coverage loss on some non-square/image transforms, including full-canvas image composites. Earlier corrected Atomics evidence depends on this change. Under the immutable instruction, reproduce against baseline and document/route around the limitation; do not silently retain the fix. A baked-image fallback can still encounter this bug on that backend.
2. **Ordinary Atomics versus forced-clockwise mode is a general semantic distinction.** `renderer_types.rs`, native mode selection and non-Metal product rejection changes expose normal Atomics separately. Forced ClockwiseAtomic can override even-odd fill behavior; it is not a interchangeable CSS oracle backend. Use the baseline's available modes honestly; raster-order and forced-clockwise results must not be conflated. No claim is made that shader exposure alone is serializable file behavior.
3. **Generated shader export binding is build robustness.** build.rs/context/pipeline/atlas/ObjC/test edits replace hardcoded minifier tokens. These became necessary when CSS shader additions changed generated names. Reverting all shader additions may remove that immediate trigger, but the generic fragility remains. It is not a CSS feature and cannot be kept without changing the immutable baseline.
4. **Tile inverse/host overflow handling is safety for the new CSS input surface.** New preflight/error state/finish abandonment addresses finite tiles whose composed coefficients overflow or whose host inverse is singular. Since the baseline has no CSS tile constructor, do not present this as proof that baseline ordinary paths had the same public bug. Compiler-emitted ordinary objects still need bounded numeric validation.
5. **Compositing dither suppression is a new rendering mode.** It prevents repeated quantization during the added offscreen opacity pipeline, while ordinary frame behavior remains. Existing baseline canvases alone do not reproduce the new intermediate-frame pixels.
6. **Exact stop lookup, two-row atlas storage, immutable tile ownership, platform glyphs, axis/hard clips and opacity planning are compiler-profile execution additions.** They must disappear from the immutable implementation, regardless of whether some are optional/default-false. Their source/file impact is fully enumerated above.

## Evidence transfer and architectural consequences

- The former exact-linear P06 gates, 64-owner atlas test, 54 Atomics composition cases, group-opacity/text visual receipts and retained benchmarks validate the modified renderer. They cannot be relabeled as baseline validation. Chrome references may be reusable only after verifying exact HTML/CSS/reset/font/image/viewport identity; native outputs must be regenerated with the immutable binary and ordinary file loading path.
- “Fully featured compiler” can mean a deep lowering pipeline: authored HTML/CSS → computed style/layout → ordinary Rive scene graph plus optional baked assets. It does not imply every authored responsive behavior remains live under arbitrary runtime resize. The compiler must explicitly choose recompilation, a proven ordinary constraint/layout representation, or a documented limitation.
- Sidecar runtime requirements, new recording commands, custom shaders, custom host renderer adapters and CSS-specific runtime policy installation are outside the new architecture. Emitting an ordinary `.riv` plus requiring any of those at load time would preserve the rejected design.
- No new native radial work is established by this commit audit. Interrupted P07 constructor/shader edits in the working tree are archived unvalidated changes and must not leak into the immutable baseline. No build was run after interruption by this task.
- This inventory is exhaustive for the three requested crate paths, not the entire PR. Runtime layout/text policy changes, compiler output dependencies, toolchain runners and repository-wide shader build inputs require the parent's separate runtime/full-PR audit. There may be file-format wrapper capabilities beyond those inspected here; absence of a demonstrated wrapper is marked unproven rather than impossible.
