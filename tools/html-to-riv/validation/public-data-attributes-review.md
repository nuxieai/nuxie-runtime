# Static data attributes (S01)

The public compiler now accepts nonempty `data-*` attributes on admitted HTML box elements. They remain on the parsed source DOM for static selector matching, then disappear: independently enumerated ID-only documents produce identical complete Rive bytes and source maps. No object properties, bindings, runtime policies, dataset API, host setters or metadata sidecars represent these attributes.

The focused implementation changes the HTML admission predicate in `src/compiler.rs` and removes the old ASCII-only attribute-name gate in `src/css.rs`. The existing `cssparser` identifier grammar and `selectors`/`scraper` matcher handle the identifiers. No dependency, schema, runtime, renderer or shared build source changed.

## Supported contract

- Attribute existence, equality, whitespace token (`~=`), exact-or-hyphen (`|=`), prefix (`^=`), suffix (`$=`) and substring (`*=`) selectors work on static custom data attributes. All existing selector combinations and cascade rules continue to apply.
- HTML folds ASCII letters in attribute names to lowercase. Literal or CSS-escaped Unicode names are admitted; ASCII letters in a Unicode name still fold, while non-ASCII characters retain case and are not normalized. The corpus distinguishes `data-café`, `DATA-CAFé`, `data-cafÉ`, literal and escaped `data-雪`, and names containing numbers, repeated hyphens, dots and colons. Colons in custom attribute names require ordinary identifier escaping; this is not namespace-selector support.
- Data values are case-sensitive by default. The `i`/`I` flag folds ASCII only. `café` and `Café` match under `i`; `CAFÉ` remains distinct. Empty and valueless attributes both have the empty string value; absence remains different. Empty prefix/suffix/substring/token searches match nothing. Exact empty equality and empty hyphen matching follow the existing selector engine and pinned Chrome.
- HTML entity decoding and line-ending normalization happen before matching. Quoted selector strings can address decoded quotes, ampersands and line breaks. Attribute values such as `var(--x)`, URLs, CSS-looking text or JavaScript-looking text remain literal source data.
- Data-selected rules can use the already admitted cascade, variables, responsive dimensions and order. Source-map identities and DOM selector order do not change when CSS order changes drawing/layout order. Inline and important precedence receive independent Rust control tests.

## Intentional boundaries

The accepted HTML attributes are `id`, `class`, `style` and `data-*` with a nonempty suffix. Bare `data-` remains diagnostic. `onclick`, `onload`, `src`, `href`, `hidden`, `contenteditable`, `tabindex`, `role` and `aria-label` are not admitted by this change. A `data-onclick` or `data-src` name carries no corresponding behavior or resource loading.

Explicit `s` remains rejected by the existing parser. The recorded pinned Chrome `153.0.8010.12` `CSS.supports(selector(...))` check returns false for `[data-state=x s]`, true for default/`i`, and true for literal/escaped Unicode data names. Namespace selectors, dynamic pseudo-classes, scripting, bindings, interactions, CSS `attr()` and mutation after compilation remain excluded. A selector selecting no elements cannot bypass unsupported declaration checks. Duplicate attribute names, including duplicates after ASCII normalization, and malformed HTML still receive the strict `html-syntax` diagnostic. The combined 1 MiB source limit is unchanged and applies to attribute payloads.

## Validation and visual review

The final corpus is `public-data-attributes-cases.json`; its 16 documents have separately authored ID-only controls with all data attributes removed. Six new Rust tests cover corpus equivalence/determinism at three viewports, inert attributes and identity, cascade, rejected behavior/resource attributes, strict grammar/declarations and the payload resource bound. All 219 Rust tests pass. All 37 Node tests pass, including 48 new CLI/WASM byte/source-map comparisons and seven identical rejection/no-output pairs. Native/WASM builds and strict TypeScript pass. All 482 bound public outputs plus 107 padding/provenance/gap controls retain exact bytes/maps. The immutable-target checker passes.

`output/public-data-attributes-r1/render-r2` contains the final native run. Each file is compiled once at 390×160 and passed as bytes alone to the unchanged baseline importer. The same original and clone are observed at 240×160 → 390×200 → 768×120 → 240×160. No metadata is passed to the importer or renderer; source maps are used later only to join read-only native geometry to Chrome DOM IDs. All 128 geometry frames, 128 native/Chrome pixel frames, 632 independent expected-paint assertions and 256 cyan/transparent clear checks pass. Every authored box is entirely visible inside every final viewport.

All 18 distinct full-frame reference/native pairs needed for review were inspected in five `review-r2-*.png` sheets: fixed-content cases at 240×160 plus all three unique responsive viewports. Colors, selected widths/heights, ordering, unchanged controls and white host/background agree. The remaining 110 pairs are independently checked through complete RGBA equality after explicit white-canvas cropping or expansion, separately for Chrome and native; the responsive case only transfers to an exactly matching viewport. This covers all 128 pairs, including original/clone and return-to-initial frames. Tolerances were unchanged.

The initial run is preserved in `render`, together with its first visual sheets/coverage receipt. It also passed its gates, but review found that later `i` rules overwrote the visible effect of earlier default-sensitive rules in seven fixtures. The final fixtures make default matches change width and `i` matches change height/color, so both predicates remain independently observable. The responsive fixture was also adjusted to keep every child inside every viewport. `coverage-refinement.json` records this evidence improvement; no compiler or tolerance change was needed. Two early Rust test-control mistakes (an incorrect diagnostic-code expectation and insufficient specificity in direct ID controls) are preserved in `initial-test-failures.json`.

`public-data-attributes-receipt.json` binds the source snapshots, final tests, binaries, browser support observation, native receipt, visual coverage and regressions. This qualifies static data selection in the documented admitted box profile. It does not qualify new layout/paint semantics or unrestricted HTML attributes.
